# SC2 로컬 7v7 커스텀 맵

> 현재 지원 제품은 **Custom AI v1.25.0**이며 진입점은
> `start_custom_ai.cmd` (`start_custom_ai_test.cmd`는 치트 테스트)이다.
> 아래 `start_7v7.cmd`/일반 API 성향 런처 설명은 초기 고정팀 맵 제작기의
> 역사적 안내다. 현재 동작은 `HANDOFF.md`와 `docs/latest_status.md`를 우선한다.

StarCraft II에서 최대 14명이 동·서 7대7로 싸우는 커스텀 맵을 만드는 프로젝트다.

목표 맵과 규칙:

- 원본: 한국 서버 `유럽 섬멸전_2` (`dddsa#517`, 14인용)
- 실제 참가자: Player 1~7 대 Player 8~14
- Player 1~7은 서쪽, Player 8~14는 동쪽 시작 지점에 고정
- Battle.net 로비 슬롯 0~6은 1팀, 슬롯 7~13은 2팀으로 고정 매핑
- 모든 광물과 가스를 풍부한 자원으로 변경하고 각 자원량을 50,000으로 고정
- SCV, 탐사정, 일벌레의 보급 비용을 0으로 변경
- 원본의 14개 플레이어 슬롯과 20개 시작 지점 후보를 삭제하지 않음

## 실제 플레이

탐색기에서 다음 파일을 더블클릭한다.

```text
start_7v7.cmd
```

또는 PowerShell에서 실행한다.

```powershell
.\start_7v7.cmd
```

설정 창에서 P1 사람과 P2~P14 AI의 종족, API 빌드 성향, 난이도를 선택한 뒤 `게임 시작`을 누른다.

현재 안정 버전은 일반 SC2 API가 지원하는 성향 가운데 `무작위`, `러쉬`, `타이밍`, `압박`, `자원`만 제공하고 `공중`은 숨긴다. 세부 지상 빌드 강제와 공중 유닛 기술 제한을 맵에 넣은 실험 버전은 시작 유닛이 누락되는 문제가 확인되어 롤백했다.

초기 기본값:

- P1과 모든 AI 종족: 무작위
- 모든 AI 빌드 성향: 자원 집중
- P2~P13 난이도: 정예
- 적 팀 P14 난이도: 자원 치터

마지막으로 사용한 설정은 `runtime/launcher_settings.json`에 자동 저장되므로 매번 코드를 수정할 필요가 없다. `기본값 복원` 버튼으로 위 설정을 즉시 되돌릴 수 있다.

## 설치

Python 환경은 기존 `.venv`를 사용한다. 맵 가공 도구의 Node 의존성은 다음 명령으로 설치한다.

```powershell
npm install --prefix .\tools
```

## 맵 빌드

> **`maps/` 에는 현재 플레이용 베이스 맵 하나만 둔다.** 원본·중간 산출물·후보 맵은
> 작업 트리에서 제거했다. 아래 명령을 다시 돌리려면 먼저 git 히스토리에서 꺼낸다:
>
> ```powershell
> git checkout cbd61c0 -- maps/source/europe-melee-2-original.SC2Map
> ```
>
> PowerShell 의 `>` 리다이렉트는 바이너리를 깨뜨리므로 `git show` 대신 `git checkout` 을 쓴다.

확보한 정확한 원본으로 다음과 같이 다시 빌드할 수 있다.

```powershell
node .\tools\build_team_map.cjs `
  .\maps\source\europe-melee-2-original.SC2Map `
  .\maps\generated\europe-melee-2-7v7-rich-50000-fixed-teams.SC2Map
```

빌더는 시작 지점 후보가 14개 이상인지 검사한다. 정확한 원본에는 14개 플레이어 슬롯과 20개 시작 지점 후보가 있으며, 이를 모두 그대로 둔 채 가장 서쪽의 7곳과 가장 동쪽의 7곳을 실제 플레이 위치로 사용한다. 중앙의 나머지 6곳에는 플레이어를 강제 배치하지 않는다. 원본의 벙커·관문 데이터 변경도 제거하여 일반 섬멸전 기본값으로 되돌리고, 세 일꾼의 보급 비용 0만 유지한다.

최종 버전은 생성된 유닛을 순간이동하지 않는다. `MapInfo`의 P1~P14 `start_point`를 지정 위치에 고정하므로 게임 엔진의 시작 위치, AI 본진 인식, 시작 건물 랠리 위치가 모두 동일하다.

빌더는 Battle.net 로비 변형도 `섬멸전 / 7 대 7`로 설정한다. 로비 팀과 내부 플레이어 번호가 뒤섞이지 않도록 표준 14인 섬멸전의 팀 슬롯 속성 `2011`을 사용해 슬롯 0~6을 1팀, 슬롯 7~13을 2팀으로 연결한다. 기존 4대4 스크립트와 사용자가 수동 수정한 자원 배치를 함께 보존하면서 7대7로 확장하려면 다음 명령을 사용한다.

```powershell
node .\tools\expand_to_7v7.cjs `
  .\maps\generated\europe-melee-2-4v4-rich-50000-melee.SC2Map `
  .\maps\generated\europe-melee-2-7v7-rich-50000.SC2Map

node .\tools\fix_player_starts.cjs `
  .\maps\generated\europe-melee-2-7v7-rich-50000.SC2Map `
  .\maps\generated\europe-melee-2-7v7-rich-50000-fixed-teams.SC2Map
```

에디터에서 열고 Battle.net에 게시할 파일은 `maps/generated/europe-melee-2-7v7-rich-50000-fixed-teams.SC2Map`이다.

게시 전에 맵 내부의 섬멸전 범주, 14개 팀 슬롯, 순간이동 코드 제거 상태를 빠르게 확인할 수 있다.

```powershell
node .\tools\verify_team_archive.cjs `
  .\maps\generated\europe-melee-2-7v7-rich-50000-fixed-teams.SC2Map
```

## 엔진 검증

```powershell
.\.venv\Scripts\python.exe -u .\verification\verify_team_map.py `
  .\maps\generated\europe-melee-2-7v7-rich-50000-fixed-teams.SC2Map
```

검증기는 SC2를 로컬에서 열어 사람 Participant 1명과 내장 AI 13명을 넣은 뒤 다음을 검사한다.

- P1~P7이 서쪽, P8~P14가 동쪽인지
- P2~P7이 P1의 동맹인지
- P8~P14가 P1의 적인지
- P1~P7 테란, P8~P14 프로토스 설정이 진영과 일치하는지
- 사람 플레이어의 시작 보급 사용량이 0인지
- 광물과 가스의 시작 자원량이 50,000인지

정확한 `유럽 섬멸전_2` 원본과 사용자의 수동 편집본으로 최종 맵을 생성했고, SC2 5.0.16에서 사람 1명과 내장 AI 13명의 실행 검증까지 통과했다. 자세한 결과는 [docs/latest_status.md](docs/latest_status.md)를 참고한다.

## Custom AI v1.25.0 전략 제어 런처

외부 ProBot을 여러 API Participant로 참가시키는 방식은 SC2 엔진의 다중 에이전트
제한 때문에 사용하지 않는다. 새 방향은 사람 한 명만 API Participant로 참가하고,
나머지 슬롯은 맵 내부 플레이어로 만든 뒤 로컬 전략 제어기가 지시하는 구조다.

현재 1단계 런처:

```text
start_custom_ai.cmd
```

구현된 기능:

- P1~P14를 각각 `비어 있음 / 사람 / 커스텀 AI`로 변경
- 사람 한 명을 어느 슬롯으로든 이동
- P1~P7 서쪽 1팀, P8~P14 동쪽 2팀 고정 배치
- AI 슬롯을 독립적으로 추가하거나 제거
- 종족별 지상군 빌드 목록의 동적 변경
- 전투 공중 유닛 생산 차단
- 수송·탐지 지원 공중 유닛 허용 여부를 실제 생산 제한에 반영
- 사람 전체 시야 테스트 옵션
- JSON 프리셋 저장 및 불러오기
- 선택한 위치 슬롯을 연속된 SC2 내부 플레이어에 매핑하는 실행용 맵 자동 생성
- 정예 내장 AI가 담당하는 자원·건설·생산 및 개별 전투 판단
- 선택 빌드 밖 지상 전투 유닛의 생산 상한을 0으로 설정
- 첫 번째 확장은 생산 건물 조건 없이 빠르게 시작
- 완성 기지 수에 맞춰 생산 건물과 목표 병력을 계속 확장
- 두 번째 확장부터 현재 단계의 생산 건물이 완성된 뒤에만 다음 확장 허용
- 확장비가 부족하면 유닛 생산을 잠깐 멈춰 400광물을 비축한 뒤 즉시 재개
- 종족별 최대 인구수 800 (일꾼 보급 비용 0 규칙과 함께 적용)
- 생산 건물 수에 비례한 요구 전투력을 실제 지상군이 충족해야만 자동 출격
- 의료선은 바이오 계열에서만 최대 4기, 메카닉에서는 0기로 제한
- 빌드와 무관한 생산 건물 수를 제한해 지상군 생산에 자원을 집중
- 사람 또는 AI 아군이 실제 적에게 공격받으면 가장 가까운 같은 팀 AI가 긴급 지원
- 지원 AI의 가용 지상군 절반을 파견하고 45초 후 내장 AI 제어로 반환
- 사람이 보거나 선택할 수 없는 인구수 0 명령 매개체를 통한 다중 AI 지휘
- 토라스크 전역 교체와 변종·랩터·골리앗·프레데터·의무병 캠페인 로스터
- 토라스크 빌드는 군락 완성 후 울트라리스크 동굴을 정상 건설 요청해 고급 테크 생략 방지
- 모든 프로토스가 공유하는 기본/아이어/네라짐/정화자/탈다림 전역 프리셋
- 진영별 원본 전용 스킬 데이터(자동시전 여부·비용·재사용 대기·효과를 원본 그대로 유지)

기본값은 P1~P4 대 P8~P11의 4대4이며 P1이 사람이다. 실행용 맵은
`runtime/maps/europe-melee-custom-ai-v1.25.0.SC2Map`에 매번 다시 만들어진다.

v1.25.0은 완전 독립 매크로 AI가 아니라 하이브리드 구조다. Blizzard 정예 AI가
경제·건설·생산과 유닛별 전술을 수행하고, 로컬 Python 전략 제어기가 맵 내부
브리지를 통해 여러 AI의 지상군 출격을 자동으로 지휘한다. GUI의 세부 빌드는
러시/타이밍/압박/자원 성향, 허용 지상 전투 유닛, 생산 건물 상한 및 목표 병력 수에
반영된다. 출격 시각은 고정하지 않는다. 완성된 관련 생산 건물 수가 많을수록 더 큰
지상군을 모은 뒤 출격하며 의료선·관측선 같은 지원 공중 유닛은 준비 전투력에서
제외한다. `무작위 지상 전략`은 지상 조합 제한 없이 내장 AI가 고르되 전투 공중만
차단한다.

메카닉의 경제 순환은 첫 확장을 생산 시설 조건 없이 진행하되 미네랄 400을
실제로 확보한 뒤 일꾼을 보내며, 이후 `2기지 공장 5 →
3기지 공장 7 → 4기지 공장 9`처럼 확장마다 공장 2개가 늘어난다. 병영과
우주공항은 기본 테크용 1개로 유지한다. 바이오와 프로토스 빌드도 첫 확장 이후
기지 수에 맞는 생산 비율로 증가하며, 저그는 첫 확장 이후 테크 조건을 적용한다.

긴급 지원은 피해 12 이상이 4초 안에 누적되고 피해 지점 20 범위 안에 실제 적이 있을
때 작동한다. 피해를 받은 플레이어가 사람이든 AI든 구분하지 않으며, 사람 시야 밖의
상대 팀 AI들도 자기 팀원을 서로 지원한다. 일꾼과 여왕은 파견하지 않고 가용 지상군의
절반, 최대 30기만 보내므로 한 번의 견제로 아군 전 병력이 비워지지 않는다. 같은 피해
지점은 30초, 지원 AI는 45초 재사용 대기시간을 둔다.

SC2는 중간의 빈 플레이어 번호를 유지하지 않고 활성 플레이어를 내부 P1부터 다시
번호 매긴다. 런처의 P1~P14는 실제 내부 ID가 아니라 고정된 시작 위치 슬롯이다.
예를 들어 위치 P2가 첫 활성 슬롯이면 게임 내부에서는 P1이지만, 시작 위치·팀·종족은
런처의 P2 설정을 그대로 사용한다.

또한 SC2는 유일한 사람 Participant를 Computer보다 항상 앞에 배치한다. 따라서 사람은
어느 위치를 고르더라도 내부 P1이며, 런처가 내부 P1의 시작점을 선택한 위치로 바꾼다.
커스텀 AI들은 내부 P2부터 이어지지만 GUI에서 고른 각 위치와 팀은 그대로 유지된다.
