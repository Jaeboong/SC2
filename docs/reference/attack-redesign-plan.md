## 0. 조사로 확정된 현재 구조 (요약)

- **수송로**: 파이썬이 P1 소유 투명 비컨 마린에게 raw move(ability 16)를 보내고 좌표가 페이로드.
  파이썬 인코딩 `sc2team/strategy_controller.py:61-81`, Galaxy 복호
  `tools/build_custom_runtime_map.cjs:953-1042`(빌더 기준 줄번호), 이벤트 구독 `:1063`.
- **인코딩 현행**: 공격류 X=100+opcode(0~99), Y=100+공격자(1~14). 지원은 X 소수부(1/100 자리)
  1~14로 판별되며 opcode 분기보다 **먼저** 검사된다(`cjs:975-981`).
- **opcode 10**: 대상 플레이어의 전 지상군(일꾼·MULE·퀸 제외, `cjs:846-856`)을 45초 스크립트
  제어 후 attack-move. 목적지는 빌드 타임 정적 테이블 `sc2team_AttackDestination`(`cjs:832-838`,
  자기 팀이 아닌 **첫 번째** 슬롯의 시작 위치 고정) — 문제 1의 근원.
- **출격 게이트**(`strategy_controller.py:160-177`): attack 쿨다운(45초) → helper 쿨다운(45초)
  → victim 쿨다운(30초) → `combat_power ≥ required_power`. 지원 판단(`:158`)이 공격보다 먼저
  실행되어 지원 발동 시 같은 사이클의 공격을 즉시 막는다 — 문제 2의 근원.
- **문턱 공식**: `required = clamp(14, 8 + 완성생산건물×6, 70)`, 전투력은 지상 유닛 인구수 합
  (`GROUND_COMBAT_SUPPLY`, `:27-38` + 실행 시 등록 4종). 빌드별 단위 불일치로 바이오는
  24~33기, 메크는 ~9기에 출격 — 문제 3의 근원. **SC2TeamMedic 등록 누락**으로 바이오 메딕은
  전투력 0(`app/play_custom_ai.py:153-158`).
- **관측**: 릴리즈 경로도 `observation(disable_fog=True)`(`app/play_custom_ai.py:148,168`) —
  전장 전체 raw 유닛이 보인다. 적 자원/인구는 API가 노출하지 않으므로 유닛·건물 카운트가 유일한
  적 규모 신호. 적 슬롯 매핑(`runtime_slots`/`runtime_player_id`)은 이미 존재하며
  `army_readiness()`를 적 슬롯에 그대로 호출해도 동작한다.
- **Galaxy 역량**: player 인자를 받는 유닛 카운트 헬퍼 7종이 이미 존재(적 번호를 넣어도 동작).
  N기 부분 선발 패턴은 지원 경로(`sc2team_IssueSupport`, 절반·최대 30기, `cjs:903-906`)에 선례.
  주기 트리거 2개(5초 ControlRelease, 15초 ProductionSteering) 가동 중.

## 0.1 적대 검증 결과 (2건)

**검증 A — 브리지 인코딩 확장안: 생존 (성립).**
X=100+opcode(정수, 소수부 0), Y=100+공격자+대상/100 확장은 기존 디코더와 충돌하지 않는다.
- X 소수부 0이면 지원 분기 오판 없음. Galaxy `FixedToInt`는 버림이며, `+0.5` 반올림 관용구가
  이를 방증하고, 현행 공격 명령(X=110.0)이 지원 검사를 이미 무해하게 통과 중이다.
- Y 정수부 복호(`FixedToInt(Y)-100`)는 소수부 존재 시에도 버림이라 안 깨진다(최대 114.14).
- 수치 안전성: float32 오차(~3.8e-6) + fixed 양자화(~2.4e-4) 합산 최악 ~2.5e-4는
  `FixedToInt(frac*100+0.5)` 기법 허용 오차 ±0.005의 1/20. 같은 파이프라인이 지원 인코딩
  X 소수부에서 이미 운용·검증 중.
- **정정 1**: 안전성의 근거는 "맵 전체 playable"이 아니라 "엔진 검증된 기존 대역(X≤110, Y≤114)의
  내부"라는 점이다. 맵 자체는 MPQ MapInfo 덤프로 256x256 전체 playable(카메라 경계 0,0-256,256)
  확인됐으나, X=111~199 대역은 엔진에서 쏴 본 적이 없다. **새 opcode는 14 이하로 유지**하면
  X≤114로 검증 대역 안에 머문다. 그 밖 대역을 쓰려면 `verify_strategy_bridge.py` 확장 프로브 필수.
- **정정 2**: "충돌 없음"이지 "그대로 동작"이 아니다. 파이썬은 새 인코더(별도 함수 또는 기본값
  있는 선택 인자 — `command_target` 기존 계약과 `tests/test_strategy_controller.py:35` 보존),
  Galaxy는 `cjs:983` 이후 Y 소수부 복호 코드를 각각 새로 추가해야 한다.

**검증 B — 목표재고 표 단일 소스("active_config_file에 실어 보내기"): 반박됨.**
- `active_config_file`은 빌더의 출력이 아니라 **파이썬이 쓰고 빌더가 읽는 입력**이다
  (`sc2team/custom_runtime.py:104-121` → `cjs:2145,2154`). 빌더에 JSON 쓰기 코드는 0건,
  그 파일을 되읽는 파이썬 코드도 0건. "이미 있는 메커니즘" 전제가 거짓.
- 표만 실어도 단일 소스가 안 된다: 기지 비례 공식(`cjs:524-528`)과 완성 타운홀 정의
  (`cjs:649-678`), bases≥1 클램프, Random 종족 분기는 파이썬에 어차피 미러가 필요.
- **채택 대안 (검증 에이전트 권장안)**: 빌더 `main()`이 출력 맵 옆에 사이드카
  `<output맵>.targets.json`을 새로 쓴다. 내용은 슬롯별 **해석 완료 값**
  `{ runtime_player, build, race, stock: { 유닛이름: { count, perExpansion } } }`
  (`perExpansion = max(1, ceil(count*0.6))`을 빌더가 계산해 실음 → 스케일링 계수까지 단일 소스).
  `build_runtime_map()`이 subprocess 종료 후 읽어 반환, 런처가 기존 `units_by_name`
  (`app/play_custom_ai.py:150-164`, RequestData 경로)으로 이름→동적 ID 변환 후 컨트롤러에 주입.
  파이썬에 남는 불가피한 최소 중복: 종족별 완성 타운홀 타입 ID 표 + `desired = count +
  (bases-1)×perExpansion` 한 줄. `active_config_file`에 합쳐 쓰는 것은 입력 계약 오염이라 비권장.

## 1. 요구사항별 실현 가능성과 설계

### R1. 동적 타겟 (죽은 적 시작 지점만 때리는 문제)

**가능. 파이썬 선택 + Galaxy 해석의 2단 구조를 채택한다.**

- **누가 고르나**: 파이썬. disable_fog 관측으로 적 팀 전원의 생존(타운홀 수)·병력 규모를 이미
  계산할 수 있고(`runtime_slots`로 팀 판별 선례 `:278,294`), "가장 약한 생존 적" 같은 정책 변경이
  맵 재빌드 없이 가능하다.
- **어떻게 전하나**: 검증 A의 인코딩 — 새 opcode 11 "대상 지정 공격",
  `Y = 100 + 공격자 + 대상적플레이어/100`. 새 인코더 함수(예: `command_target_with_param()`)를
  추가하고 `command_target`은 그대로 둔다.
- **Galaxy 목적지 해석**: opcode 11 분기에서 대상 플레이어의 **현재 완성 타운홀 중 하나의 위치**
  (기존 CountCompletedTownHalls 패턴을 위치 반환형으로 변형)를 목적지로, 타운홀이 없으면 잔존
  유닛 위치, 그마저 없으면 기존 `sc2team_AttackDestination` 폴백.
- **생존 판정**: PlayerStatus 네이티브는 존재하지만 제거된 Computer의 상태 전이 시점이 미검증
  이므로 **유닛 카운트 방식**(타운홀>0)을 쓴다. 파이썬 쪽 판정이므로 Galaxy 수정 최소.
- opcode 10(현행 전량·고정 타겟)은 폴백으로 유지 — 양방향 호환.

### R2. 쿨다운 (지원 쿨다운이 공격을 영구 봉쇄)

**가능. 가장 싸고 효과가 확실한 수정.**

- `update()`의 공격 루프에서 helper/victim 쿨다운 게이트(`:164-167`) **제거**. 공격 자체 쿨다운
  45초(`_attack_cooldown_until`)만 남긴다. 지원 시스템(트리거·선정·발송·자체 쿨다운)은 그대로.
- 근거: 기존 테스트 어느 것도 이 게이트를 단언하지 않아 제거만으로는 안 깨짐(검증됨).
  Galaxy 쪽은 지원/공격이 같은 유닛 풀을 `c_orderQueueReplace`로 덮어쓸 뿐 상호 배제가 없으므로,
  겹침의 실질 비용은 "지원 나가던 절반이 공격 목적지로 방향 전환" 수준 — 영구 봉쇄보다 훨씬 낫다.
- 부수 수정: `_Threat`의 4초 창은 진짜 롤링 윈도우가 아니라 "4초 공백 시 리셋"이라 3초 간격
  피해가 이어지면 무한 누적된다(`:97-105`). 지속 교전 중 30초마다 지원이 재발동하는 원인.
  1차 수정에서는 건드리지 않고(공격 봉쇄만 풀면 치명도가 낮아짐), 실측 후 필요 시
  발동 즉시 임계 리셋 등으로 손본다.
- **신규 테스트(TDD)**: game_loop를 30/45초 넘게 진행시키는 다중 update() 시퀀스로
  (a) 지원 발동 직후에도 문턱 충족 시 공격이 나감, (b) 공격 쿨다운 만료 후 재공격,
  (c) 지원 쿨다운 만료 후 재지원을 단언. 기존 fixture 헬퍼(observation/_unit/FakeConnection) 재사용.
- 주의: `test_nearest_ai_supports_damaged_human_ally`의 `commands[-1]` 단언은 "공격 무발신"
  암묵 전제(가짜 유닛 전투력 0이 이중 안전망) — 게이트 제거만으로는 안 깨지지만 인지하고 갈 것.

### R3. 출격 문턱 (빌드별 단위 불일치 → 목표재고 달성률 기반)

**가능. 사이드카 JSON(검증 B 대안)으로 표를 단일 소스화한다.**

- **즉시 수정(문턱 교체와 무관한 확정 버그)**: `custom_combat_supply`에 `SC2TeamMedic: 1.0`
  추가(`app/play_custom_ai.py:153-158`). 바이오 메딕이 전투력 0으로 계산되는 누락.
- **새 문턱**: `달성률 = 현재 지상 전투력 합 / 목표 재고의 전투력 환산 합` ≥ 임계(초안 0.7)에서
  출격. 분모는 사이드카 표의 `count + (완성기지-1)×perExpansion`을 유닛별 인구수 가중으로 환산.
  완성 기지 수는 파이썬 관측으로 카운트(종족별 타운홀 타입 ID 표 신설, `build_progress ≥ 0.99`,
  최소 1 클램프 — Galaxy `cjs:649-678,486-488` 미러).
- **폴백**: `random_ground` 빌드(표 없음)와 race="Random" 슬롯(종족도 사전 미확정,
  `custom_runtime.py:67-75`에서 엔진이 뽑음)은 현행 producer 공식 유지. 현행 공식은 이미
  종족 불문으로 동작한다(`PRODUCER_TYPES_BY_BUILD["random_ground"]`가 전 종족 합집합).
- **테스트 교체**: `test_attack_readiness_scales_with_production_and_ignores_medivacs`의
  `required==14.0/20.0` 단언은 반드시 깨진다 → 새 공식 단언으로 교체하되 "공중 무시"·"producers
  카운트" 단언은 유지. §51 재현 시나리오(바이오 24기 출격 가능 / 메크 소수 미출격)를 새 단언으로
  명시. `test_controller_caches_beacon...`의 `army_readiness` 람다 스텁(3-튜플 계약)도 반환 형태
  변경 시 동반 수정.
- 과거 이력 참고: 시간 기반 출격(v1.1.0)은 "시간만 되면 쥐꼬리 병력 출격"으로 폐기된 유일한
  선행 실험. 마릿수/달성률 기반은 시도된 적 없음. §50 교훈에 따라 생산(부속건물) 강제로 우회하지
  않는다 — 재설계 범위는 출격 판단 로직으로 한정.

### R4. 정찰 기반 판단 (적 규모 관측)

**가능. 신규 관측 코드가 거의 필요 없다.**

- 관측은 이미 전지적(disable_fog). 적 슬롯에 `army_readiness()` 호출 또는 동일 테이블로
  적 지상 전투력·타운홀·일꾼·테크 건물 카운트 가능. 적 자원/인구만 불가(API 미노출, HANDOFF 명시).
- **1차 활용(R1의 입력)**: 타겟 선정 = 같은 팀이 아닌 생존자(타운홀>0) 중 지상 전투력 최소인
  플레이어. 인간(runtime 1)도 적 팀이면 후보(빌드가 없으니 전투력만 비교).
- **2차 활용(선택, 실측 후)**: 상대 전력비 출격 보정 — 내 전투력 < 대상 방어 전력 × 계수면 출격
  보류. 1차 구현에는 넣지 않는다(문턱 재설계와 겹쳐 원인 분석이 어려워짐).
- 미확정: 적 유닛 `build_progress`가 raw 관측에서 항상 정확한지, Computer의 확정 종족
  (race_actual)이 노출되는지는 엔진 측정 필요 — Phase 3 엔진 테스트에서 함께 확인.

## 2. 구현 순서 (Phase)

HANDOFF 권장 순서(타겟→쿨다운→문턱)는 "효과 크기" 기준. 실제 구현은 위험·의존성 기준으로
쿨다운을 먼저 푼다(코드 1~2줄 + 테스트, 즉시 효과 실측 가능).

| Phase | 내용 | 검증 |
| --- | --- | --- |
| A | R2 쿨다운 게이트 제거 + SC2TeamMedic 등록 + 신규 쿨다운 시퀀스 테스트 | offline 티어 + short-engine |
| B | R3 사이드카 JSON(빌더 출력 + 파이썬 읽기 + 이름→ID 변환) + 달성률 문턱 + 테스트 교체 | offline 티어(빌더 구조 검증 포함) + release-engine 실측 |

## 3. 제약 체크리스트 (CLAUDE.md 불변식 대조)

- 비컨 좌표 인코딩 유지(Participant 1명 불변) — 새 opcode도 X 소수부 0 유지로 지원 분기와 충돌 없음.

- 생성 맵 직접 수정 금지 — 모든 Galaxy 변경은 빌더에서, 재생성으로 반영.
- customValue 슬롯: 26·31·구매 슬롯 사용 중 — 새 유닛별 상태 저장 시 회피.
