## 51. 테란 공격 규모 조사 — 원인 규명 (2026-07-17)

### 51.1 사용자 증상

"중후반에도 테란 병력이 매우 적다. 공격받아도 잘 뽑지도 않는다. 잘 뽑는 애들이
있긴 한데 그래도 적다. 공격 가는 병력 수가 거의 10마리 수준이다. 반면 프로토스는
20~30기 수준으로 공격하며 서로 협동 공격도 한다. 지들끼리 뭉쳐서 동시다발적으로
공격한다."

### 51.2 측정

### 51.3 원인 세 가지

**(1) 모든 AI가 첫 번째 적 슬롯 하나만 공격한다.**
`build_custom_runtime_map.cjs`의 `attackTargets`:

```js
const enemyIndex = activeSlots.findIndex((other) => other.team !== slot.team);
const enemyPlayer = enemyIndex >= 0 ? enemyIndex + 1 : humanRuntimeId;
return `if (player == ${index + 1}) { return PlayerStartLocation(${enemyPlayer}); }`;
```

런타임 순서가 `(인간, AI들...)`이므로 사용자 설정에서:
- 테란 5명 전원 → r7 = P8. P8은 5:1로 맞아 일찍 죽고(t=600에 병력 0, 생산건물 0),
  그 뒤 테란의 모든 공격은 시체의 빈 시작 지점으로 걸어가는 행군이 된다. P9~P13은
  아무도 공격하지 않는다.
- 프로토스 6명 전원 → 인덱스 0 = 인간. 사용자가 "협동 공격"으로 느낀 것은 협동
  로직이 아니라 전원이 같은 한 곳을 치는 것이다.

**(2) 1팀은 사실상 영구 공격 금지 상태다.**
`strategy_controller.py:164-167`:

```python
if elapsed < self._helper_cooldown_until.get(runtime_player, 0.0):
    continue
if elapsed < self._victim_cooldown_until.get(runtime_player, 0.0):
    continue
```

지원 발동 시 피해자는 30초, 지원자는 45초 공격 금지에 걸린다. 프로토스 6명이 1팀을
계속 때리므로 지원이 계속 발동하고, 테란은 쿨다운에서 벗어나지 못한다. P5는 t=480에
39/38로 문턱을 넘고도 t=600까지 120초 넘게 공격 0회였다. 테란 5명 중 P1만 공격했다.

**(3) 문턱이 마릿수가 아니라 인구수로 계산된다.**
`required_power = 8 + producers * 6` (상한 70), `combat_power`는 `GROUND_COMBAT_SUPPLY`
인구수 합. 두 값의 단위가 달라 종족·빌드마다 필요 마릿수가 크게 어긋난다.

| 빌드 | 요구 전투력 | 유닛 무게 | 필요 마릿수 |
| --- | --- | --- | --- |
| mech_macro | 38 (군수공장 5) | 프레데터 3.0 | 9~17 |
| bio_tank | 50 (병영+공장 7) | 해병 1.0 | 27마리로도 미달 |
| gateway 계열 | 50 (관문 7) | 추적자 2.0 | 22 |

`PRODUCER_TYPES_BY_BUILD`에서 mech_macro는 군수공장(27)만 세고 gateway 계열은
관문+차원관문(+로보)을 센다. 테란 기계화는 문턱이 낮은데 유닛이 무거워 10마리에
넘어버리고, 바이오는 문턱이 높은데 유닛이 가벼워 27마리로도 못 넘는다.

### 51.4 부수 발견

`app/play_custom_ai.py:153-158`의 `custom_combat_supply`에 `SC2TeamMedic`이 빠져
있다. 토라스크·아버레이션·골리앗·프레데터는 등록되지만 메딕만 전투력 0으로 계산된다.

### 51.5 상태

미수정. 세 원인 모두 게임 밸런스를 바꾸는 변경이라 사용자 판단을 기다린다.
권장 순서는 (1) → (2) → (3). 시체를 공격하는 것은 명백한 버그이고, 이것만 고쳐도
테란 5명의 공격이 살아있는 적에게 분산된다.

50절의 "mech_macro 초반 10분 공백"은 여전히 유효하나, 본 절이 밝힌 원인에 비하면
부차적이다. 50절에서 "테란 병력이 프로토스보다 많다"고 측정한 것은 2v2 구성이었고,
사용자의 5 vs 6 구성에서는 위 세 원인이 겹쳐 다르게 작동한다.

## 52. 공격 시스템 재설계 요구사항 조사 — 계획 확정 (2026-07-17)

51절의 세 원인에 대해 사용자가 방향을 정했다: (1) 전장 상황 기반 동적 타겟,
(2) 쿨다운 문제도 같은 방향으로, (3) 인구수 문턱 대체 + 생산 규모 비례 출격 규모,
(4) 가능하면 자기 생산 규모 대신 관측된 적 병력·전황 기반 판단.

### 52.1 조사 방법

코드 조사 4영역(브리지 수송로 / Galaxy 생성부 / 컨트롤러 관측 / 문턱·이력)을 병렬
정독하고, 누락 점검으로 후속 조사 4건(_Threat 수명, 기존 단위테스트 계약, 맵
playable 경계 MPQ 덤프, random_ground 종족 확정 시점)을 추가했다. 설계의 핵심 주장
2건(브리지 인코딩 확장, 목표재고 표 단일 소스)은 적대 검증을 거쳤고 그중 1건이
반박되어 설계를 수정했다.

### 52.2 결론 요약

네 요구사항 모두 실현 가능하다. 근거가 되는 확정 사실:

- 릴리즈 런처도 `observation(disable_fog=True)`라 파이썬 컨트롤러는 이미 안개 없는
  전장 전체를 본다(`app/play_custom_ai.py:148,168`). "정찰"은 새로 만들 필요가 없고,
  적 병력·타운홀·일꾼 카운트가 전부 가능하다. 적 자원/인구만 API가 노출하지 않는다.
  AI별 공정 시야는 Participant가 1명이라 구조적으로 불가 — 전지적 관측이 유일한 선택.
- 브리지 인코딩은 Y 소수부가 미사용이라 대상 플레이어(1~14)를 실을 수 있다.
  fixed 1/4096 + float32 오차 합산이 허용 오차의 1/20이라 안전하고, X 소수부 0이면
  지원 분기 오판도 없다. 단 X=111~199 대역은 엔진 미검증이라 새 opcode는 14 이하 유지.
- Galaxy에는 player 인자 카운트 헬퍼 7종과 N기 부분 선발 패턴(지원 경로, 절반·최대
  30기)이 이미 있어 동적 목적지·부분 출격 모두 기존 패턴 재조합이다.
- 지원 쿨다운 게이트(`strategy_controller.py:164-167`)는 어떤 테스트도 단언하지 않아
  제거만으로는 기존 테스트가 깨지지 않는다. `_Threat`의 "4초 창"은 롤링 윈도우가
  아니라 4초 공백 시 리셋이라 지속 교전 중 무한 누적된다 — 영구 봉쇄의 나머지 절반.
- "목표재고 표를 `active_config_file`로 공유" 안은 **반박됐다**: 그 파일은 파이썬이
  쓰고 빌더가 읽는 입력이다. 대안으로 빌더가 출력 맵 옆에 사이드카
  `<맵>.targets.json`(슬롯별 해석 완료 재고 표)을 쓰고 파이썬이 되읽는 경로를 채택.

### 52.3 산출물

계획 전문은 `docs/reference/attack-redesign-plan.md`. 구현 순서는 위험·의존성 기준으로
A(쿨다운 게이트 제거 + SC2TeamMedic 등록) → B(사이드카 표 + 달성률 문턱) →
C(opcode 11 대상 지정 공격 + Galaxy 동적 목적지) → D(선택: 부분 출격, 상대 전력비).
아직 코드는 수정하지 않았다.

## 54. 재설계 Phase B 완료 — 사이드카 재고 표 + 달성률 문턱 (2026-07-17)

§51 원인 3(빌드별 단위 불일치 문턱)을 목표재고 달성률 문턱으로 교체했다.

### 54.1 변경 내용

- `tools/build_custom_runtime_map.cjs` — `makeStockTargets()` 신설. `main()`이 출력
  맵 옆에 `<맵>.targets.json` 사이드카를 쓴다. 내용은 custom_ai 슬롯별
  `{runtime_player, logical_slot, build, race, stock: {유닛이름: {count,
  perExpansion}}}`. `perExpansion`은 경제 규칙과 같은 공식
  `max(1, ceil(count*0.6))`을 빌더가 미리 계산해 실어 스케일링 계수까지 단일
  소스다. Random 종족은 Galaxy가 재고를 확장 비례 없이 걸므로(빌더 :478-483)
  0으로 미러한다. **맵(Galaxy/카탈로그) 내용은 무변경** — 맵 버전 유지.
- `sc2team/custom_runtime.py` — `stock_targets_path()`/`load_stock_targets()` 신설
  (버전 검사 포함), `build_runtime_map()`이 사이드카 부재 시 실패.
- `sc2team/strategy_controller.py` — 재고 표가 주입된 슬롯의 문턱을
  `목표재고 환산 전투력 × 0.7`(`ATTACK_STOCK_READINESS_RATIO`)로 교체.
  기지 수는 종족 불문 타운홀 합집합 `TOWN_HALL_TYPES`(플레이어는 자기 종족
  타운홀만 지으므로 안전, Random도 판별 불요)로 세고, 완성(`build_progress ≥
  0.99`)만 센다. 0기지는 1로 클램프, 문턱은 기존 [14, 70] 클램프를 그대로 적용해
  "다기지에서 영영 미출격" 퇴행을 차단. 재고 표 없는 슬롯(random_ground 빌드)은
  기존 producer 공식 폴백 — 그래서 기존 문턱 테스트(14.0/20.0 단언)는 폴백
  검증으로 그대로 살아남았고 교체가 불필요했다. `army_readiness` 3-튜플 계약 유지.
- `app/play_custom_ai.py` — 사이드카를 읽어 `units_by_name`으로 이름→동적 ID 변환
  후 `set_stock_targets()` 주입. 캠페인 유닛(메딕 포함)의 동적 ID도 이 경로로
  해결된다.
- `verification/verify_all.py` — offline 구조 검증이 픽스처마다 사이드카를 되읽어
  "모든 custom_ai 슬롯 존재 + random_ground 이외 빌드는 재고 표 비어 있지 않음"을

  [14, 70] 클램프와 0기지 클램프, 비 AI 슬롯 주입 거부, 사이드카 로더 정상/버전

## 57. 지원 치명 판정 — 지원 111회 → 60회 (2026-07-17)

§56의 "지속 교전 중 지원 30~45초 재발동" 관측에 대해 사용자가 물었다:
"치명적 손실이 우려되는 교전이나 기지가 파괴될 수준을 측정 판단이 가능한가?"
가능하다고 답했고("그렇게 바꾸자, 지원남발은 좋지않다") 구현했다.

### 57.1 설계

기존 지원 트리거는 "4초 창에 피해 12 이상 + 반경 20 안에 적 존재"뿐이라
**이기고 있는 교전에도 지원이 나갔다.** `_dispatch_supports`에 치명 문지기
`_threat_is_critical()`을 추가해, 피해 조건을 넘어도 아래 셋 중 하나여야
파병한다. 재료는 전부 기존 1초 간격 전맵 스냅샷(`_health_snapshot`)에 있다.

1. **기지 위협** — 피해자의 타운홀이 실제로 맞았다(피격 또는 파괴).
2. **국지 전력 열세** — 피해 중심점 반경 20 안에서 적 지상 전투력이 아군의
   1.5배 이상이고(`SUPPORT_OUTNUMBER_RATIO`), 최소 8 이상
   (`SUPPORT_MIN_ENEMY_POWER` — 마린 두엇 일꾼 견제 배제).
3. **급격한 손실** — 위협 창 동안 잃은 전투력이 (현재+손실)의 20% 이상
   (`SUPPORT_LOSS_RATIO`).

부수 개선: **전사 감지**. 스냅샷에서 사라진 유닛의 남은 체력을 피해로,
전투력을 손실로 누적한다(`_Threat.lost_power`). 종전에는 생존자 HP가 안
깎이면(한 방에 죽는 유닛만 잃는 교전) 위협 자체가 안 잡혔다. 스냅샷 튜플에
unit_type이 추가됐고(`(owner, unit_type, health, x, y)`), 가중치 조회는
`_combat_weight()`로 단일화했다.

### 57.2 1차 실측이 반증한 설계

처음에는 "피해 중심점이 타운홀 반경 15 안"도 기지 위협으로 넣었다. 16게임분
실측 결과 지원 111회 → **109회**로 사실상 무효과. 멜리 AI의 교전은 대부분
기지 앞에서 벌어지므로 위치 기준은 만능 통과 조항이었고, 초반 일꾼 견제도
(일꾼 전투력 0 → 아군 전력 0 → 마린 2기가 1.5배 초과) 열세로 잡혔다.
위치 조항을 삭제하고 최소 적 전력 8을 추가한 것이 위 최종 설계다.

### 57.3 결과 (조인 뒤 재실측, §56과 같은 조건 16게임분)

- **지원 111회 → 60회.** 특히 초반이 조용해졌다: 500s 이전 지원이 §56
  ~12회 → 3회. 후반 대규모 교전에서는 열세·손실 기준이 정상 발동한다.
- **출격 21회 → 27회, 첫 출격 ~718s → ~570s.** 지원 원정이 줄어 병력이
  집에 쌓이면서 문턱 도달이 빨라진 것으로 보인다(§56.2의 "첫 출격 늦음"
  우려가 조절 없이 완화됨). 출격 규모는 22~41기로 §56 수준 유지.
- 동적 타겟 동작 유지: 최약 생존 적이 P6 → P5 → P2(전멸) → P3 → P4 → P1로
  이동하는 것을 추적.

### 57.4 검증

- TDD 신규 테스트 5건(레드 확인 후 구현): 이기는 교전 지원 억제, 국지 열세
  발동, 소규모 견제 비발동(최소 전력 8), 타운홀 피격 시 전력 우세와 무관하게
  발동, 전사 감지(생존자 HP 무변화 + 20% 손실). 총 21건.

  경로로 무수정 통과 — 파이썬 전용 변경이라 맵/버전 무변경(v1.11.0 유지).

### 57.5 사용자 유의 — 전투 페이스 오인 가능성
