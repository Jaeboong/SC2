# 작업 하네스

이 프로젝트에서 **누가 무엇을 하는지**, 그리고 **무엇을 통과해야 "됐다"고 말할 수 있는지**를 정한다.
규율(무엇을 고치면 안 되는가)은 여기 없다. [`README.md`](README.md)의 라우팅 표를 따라간다.

## 역할

| 역할 | 담당 | 하는 일 | 하지 않는 일 |
| --- | --- | --- | --- |
| 헤드 에이전트 | Claude | 원인 진단·측정, 작업 명세 작성, 결과 검증, 사용자 보고, **문서 작성** | 게임 코드 직접 편집 |
| 작업자 | Codex (`codex:codex-rescue`) | 코드 수정, 매니페스트 갱신, 정적 검증 | 엔진 프로브, 커밋, 문서 구조 변경 |
| 최종 판단 | 사용자 | 게임 동작 변경 승인, 커밋 승인, 라이브 육안 검증 | — |

- **게임 동작을 바꾸는 진단은 수정 전에 먼저 보고하고 동의를 받는다.** 원인을 찾았다고
  바로 고치지 않는다.
- **엔진 검증은 헤드 에이전트가 직접 돌린다.** SC2 프로브는 18분씩 걸리고 중간 상태를
  봐야 한다. Codex에는 코드 편집 + 정적 검증 + mod 빌드 해시 확인까지만 맡긴다.
- **문서는 헤드 에이전트가 쓴다.** Codex에 문서를 맡기면 기존 문서를 복사해서 새 파일을
  만드는 쪽으로 흐르고, 그게 이 하네스가 한 번 무너졌던 원인이다(아래 "복사 금지" 참조).

### Codex 위임 규약

```
codex:codex-rescue 서브에이전트, effort medium, write 모드
```

**`--model` 플래그를 붙이지 않는다.** 이 ChatGPT 계정은 `gpt-5.6` 지정을 거부한다
(`invalid_request_error: 'gpt-5.6' model is not supported when using Codex with a ChatGPT account`).
모델은 기본값을 쓴다.

명세에 **반드시** 포함할 것:

1. 대상 파일 (전체 경로). 그 외 파일은 건드리지 않는다고 명시.
2. 지켜야 할 불변식 — 해당 계층 규율 문서를 링크하고, 이번 작업에 걸리는 항목은 본문에 인용.
3. **금지 사항 4종** (매번 반복):
   - 사용자 맵(`maps/generated/**`) 및 미추적 파일 불가침
   - 커밋 금지 (사용자가 명시적으로 지시할 때만)
   - `v3/ai/upstream/**` 읽기 전용
   - 검증기를 통과시키려고 검증기 자체를 수정 금지
4. 수용 기준 — 아래 검증 게이트 중 이번 작업에 해당하는 것.

병렬 위임(여러 Codex 동시)은 **각자 서로 다른 파일만 소유할 때만** 허용한다. 공유 자산
목록과 처리 규칙은 [`ownership.md`](ownership.md)에 있다.

## 검증 게이트

작업 유형별로 무엇을 통과해야 하는지. 위에서 아래로 갈수록 비싸다.

| # | 게이트 | 명령 | 잡는 것 |
| --- | --- | --- | --- |
| 1 | 구문 | `node --check <file>` / `py_compile` | 문법 오류 |
| 2 | V3 구조 | `.\.venv\Scripts\python.exe v3\verification\verify_v3_structure.py` → `V3_STRUCTURE=PASS` | 파일 목록·해시·마커 |
| 3 | V3 mod 빌드 | `node v3\tools\build_v3_ai_mod.cjs <출력.SC2Mod> <plan.json>` → `V3_AI_MOD_BUILD=PASS` | 패키징·업스트림 해시 |
| 4 | 오프라인 tier | `.\.venv\Scripts\python.exe verification\verify_all.py --tier offline` | 맵 빌더 회귀 (픽스처 12종) |
| 5 | **스모크 (6분)** | `probe_v3_ground_builds.py --duration 360` | **galaxy 컴파일 깨짐** |
| 6 | 전체 프로브 (18분) | `probe_v3_ground_builds.py --all-<build> --mirror-count 12 --duration 1080 --report <out.json>` | 생산·전투 실측 |
| 7 | 라이브 육안 | 사용자가 직접 플레이 | 미시 행동 |

### 게이트 5는 생략할 수 없다

**1~4번은 galaxy 컴파일 에러를 하나도 못 잡는다.** 넷 다 PASS인데 게임에서 전 슬롯이
일꾼 0·건물 0으로 죽은 사례가 §108에서 두 번 나왔다:

- `AITechStockAdd(player, x)` — 이 네이티브는 인자가 **하나**다. 인자 개수 오류.
- `PointWithOffsetPolar` 사용 및 C 스타일 배열 선언 — 오버레이 스코프에 없는 심볼.

정적 검증기는 파일 목록·SHA-256·마커 문자열만 본다. mod 빌더는 패키징만 한다. 프로브의
`GROUND_COMPILE=PASS`조차 "맵 로드 + 카탈로그 읽힘"이지 트리거 컴파일 성공이 아니다.
**SC2는 이 환경에 galaxy 에러 로그를 남기지 않는다.** 그래서 오버레이 `.galaxy`를 한 줄이라도
고쳤으면 6분 스모크가 필수다.

컴파일 깨짐이 의심되면 **`--upstream-timing`**(V3 mod 미설치, 블리자드 순정 AI)으로 격리한다.
정상 스폰이면 범인은 V3 mod, 여전히 플레이어 0이면 맵/환경 문제다. 5초 시점 `RAW_OWNERS`
한 줄로 판별된다.

### 엔진 프로브는 배타 실행 — 점유 전후로 A2A 통보 (필수)

SC2 인스턴스는 하나뿐이고 API 포트가 고정이다. **두 담당자가 동시에 돌리면 둘 다 무효가
된다.** 프로브 전에 SC2와 SC2 에디터를 닫는다.

**SC2를 쓰는 모든 작업은 시작 전과 종료 후에 A2A로 다른 세션에 통보한다.** 18분 프로브만이
아니라 6분 스모크, 육안 확인용 비주얼 프로브까지 전부 해당한다. 실제로 세션 하나가 점유
통보를 누락해서 상대가 "SC2 비어 있음"으로 오판한 사례가 있었다.

```bash
A2A="C:/Users/cbkjh/OneDrive/바탕 화면/M/Play/A2A/bin/a2ab.mjs"
ME=<내 sessionId>

# 목록 확인 (활성 세션과 각자 만지는 파일)
node "$A2A" peers --session $ME

# 점유 시작
node "$A2A" send --from $ME --to "startcraft2/<상대>" --kind notification \
  --text "[<내 역할>] SC2 점유합니다: <무엇을, 몇 분>. 끝나면 알립니다."

# 점유 해제
node "$A2A" send --from $ME --to "startcraft2/<상대>" --kind notification \
  --text "[<내 역할>] SC2 점유 해제."
```

- 상대 지정은 **`startcraft2/<id>` 표시 이름 형식**을 쓴다. 짧은 id만 주면
  `unknown session`으로 거부된다.
- 통보는 `notification`(턴을 깨우지 않음), 답이 필요한 조율은 `request`(응답 의무).
- 활성 세션 **전부**에 보낸다. 누가 프로브를 돌릴지는 미리 알 수 없다.
- 점유 중 다른 세션이 편집한 오버레이가 섞여 들어갈 수 있다. 프로브 결과가 이상하면
  내 변경만이 아니라 **그 시점 작업 트리 전체**가 측정 대상이었음을 기억한다.

### `--report` 경로는 미리 존재 확인

프로브는 18분을 다 돌린 **뒤에** 리포트를 쓴다. 경로를 손으로 타이핑했다가 디렉토리가
없으면 그 시점에 실패하고 측정을 통째로 잃는다. 시작 전에 `ls -d`로 부모 디렉토리를
확인하거나 `mkdir -p` 한다. (이미 돌고 있는 프로브라면 죽이지 말고 그 경로를 만들어 주면
그대로 받을 수 있다.)

## 진단 규율

반복해서 틀렸던 방식들이다. 각 항목은 실제로 값을 치르고 배운 것이다.

- **닫힌 게이트는 코드를 읽어서 진단하지 말고, 실험 빌드에서 우회해서 진단한다.**
  §91.10은 게이트가 닫혀 있는 줄 모르고 그 뒤의 죽은 코드를 두 번 고쳤다. `return true`
  두 줄짜리 실험 하나와 단일 항 실험 하나로 두 번 만에 범인을 특정했다.
- **"AI가 고장났다"는 보고가 오면 엔진보다 우리 오버라이드를 먼저 의심한다.** 최근 기록
  §88·§96·§98·§103·§104가 전부 우리 것이었고 멜리 AI 잘못은 하나도 없었다.
- **자원 부족은 원인이 될 수 없다.** 베이스 맵이 rich(50000)다. 가스는 쓸 곳이 없으면
  쌓인다. "자원/가스 기아" 류 진단은 하지 않는다. `AIHasRes` 게이트는 사실상 항상 참이다.
- **정체한 슬롯 하나를 버그로 읽지 않는다.** 7v7에서 한 슬롯이 안 크는 것은 보통 초반
  피해다. 추세와 슬롯 분포로 판단한다.
- **계측 두 열이 서로 모순되면 게임이 아니라 프로브를 의심한다.** 논리 슬롯과 런타임 ID를
  섞는 실수가 두 번 있었다.
- **시각적 미시행동은 프로브로 검증하지 않는다.** 회군·방어·후퇴전투·합류 같은 행동은
  SC2 API로 보이지 않는다. 집계 수치(유닛 수·건물 수·보급)만 프로브로 보고, 나머지는
  사용자 라이브 육안이다.
- **엔진이 거부하는 주문은 조용히 무시된다.** `UnitOrderIsValid`가 false를 돌려주고 끝이다.
  에러가 없다. 같은 순간 같은 대상에 대조군 유닛을 함께 측정해야 한다.

## 문서 규율

- **복사 금지.** 같은 내용이 두 파일에 있으면 반드시 어긋난다. `AGENTS.md`가 `CLAUDE.md`의
  164줄짜리 수동 복사본이었고, 그래서 정작 작업자가 봐야 할 하네스 규율만 빠져 있었다.
  내용은 한 곳에 두고 나머지는 링크한다.
- **진입점은 라우터다.** `CLAUDE.md` / `AGENTS.md`에는 규율 본문을 넣지 않는다. 넣기
  시작하면 다시 180줄이 된다.
- **링크가 깨지면 진입점이 죽는다.** 두 진입점 파일이 동시에 존재하지 않는
  `HANDOFF.md`를 가리킨 적이 있다. 문서를 옮기면 `verification/check_doc_links.py`를
  돌린다(오프라인 tier에 포함).
- 작업 로그(`latest_status.md`, `v3/docs/status.md`)는 **덧붙이고 고쳐 쓰지 않는다.**
  실패한 시도와 폐기된 주장도 남긴다. 현재 동작은 코드가 authoritative다.
