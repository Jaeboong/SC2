change: the split was verified by rebuilding every fixture and the release map to
byte-identical output).

| `tools/build_custom_runtime_map.cjs` | CLI entry, orchestration order, stock sidecar |
| `tools/build/util.cjs` | `fail`, path constants, `readGalaxyTemplate` (no build/ deps) |

Rules when working here:

- A `.galaxy` file under `tools/galaxy/` is raw Galaxy source with **no `${}`
  interpolation**. `readGalaxyTemplate` normalizes CRLF to LF because JS template
  literals do the same per spec; removing that normalization changes the built map
  on a CRLF checkout. Keep interpolated Galaxy in the `.cjs` template literals.
- Galaxy needs declaration before use, so keep the assembly order bridge → production
  in `runtime.cjs`. The old §60 claim that the economy block reuses
  `sc2team_IssueSupport` was audited false on 2026-07-22 (its only caller is the
  bridge itself); the order is now preserved for byte-identical output, not for a
  cross-block dependency. Unit control and production share **no** globals, no
  custom values (30/31 vs 18/20/21/22), and no rosters.
- `tools/build/util.cjs` must not require any other `build/` module (cycle guard).
- Path constants live only in `util.cjs`. Do not reintroduce `path.join(__dirname, "..")`
  in a `build/` module; the depth differs from the old single-file layout.
- After any builder change, the regression oracle is a **byte-identical rebuild**:
  the offline tier's seven fixtures are deterministic, so a pure refactor must not
  move a single byte. Delete `runtime/maps/verify-all-*` before comparing — a failed
  build leaves the previous maps on disk and reads as a false match.

## Non-negotiable invariants

- **Our Galaxy/Python layer is a supplement (보조), never the primary system (주)** —
  standing user directive (§104). Blizzard's melee AI owns the game. Our code exists
  for exactly three jobs: (a) **raise its output** by assisting expansion, supply, and
  unit production; (b) **steer it to the configured build**; (c) **forbid specific unit
  types**. Anything beyond those three is out of scope by default and needs the user's
  explicit approval. Concretely, and each of these was learned by breaking it:
  - **Never stall the melee AI build manager.** §83 measured that an unmet-prerequisite
    `AIBuild` repeated every tick permanently freezes a slot — zero workers, army, and
    expansions for 20 game-minutes. Any forced-construction order needs its latch and
    its any-of prerequisite gate, and adding a new one is a behavior change, not a tweak.
  - **Never take a shared resource the melee AI needs.** Orbital Command energy is the
    worked example: our Supply Drop consumed every 50 the moment it regenerated, so the
    melee AI could never afford Scanner Sweep or a MULE. The rule is now "spend only
    above 100", i.e. leave its half untouched. Apply the same reasoning to any future
    ability, bank, or production slot we spend from.
  - **Prefer filling a gap over overriding a decision.** Research (§63), Terran addons
    (§82), and infrastructure rebuilds (§71) exist because the melee AI provably does
    not do them on this map — that is assistance. Taking over a decision the melee AI
    *does* make (which unit to command, where to expand) is the opposite, and every
    instance of it in this repo has produced a user-visible regression.
  - When a "the AI is broken" report arrives, **suspect our override before the engine.**
    The recent record is §88 supply gate dead for three versions, §96 expansion allowance
    self-cancelled, §98 allowance emitted after the order, §103 pylons ordered onto
    unreachable high ground — all ours, none the melee AI's.

- There is exactly one SC2 API `Participant`; every AI player is an in-game `Computer` player. Exception (§66 observer mode, test launcher only): the game is created with NO Participant — every slot is a Computer and the API joins as the sole `Observer`. Runtime IDs keep the same human-slot-first order either way.
- The sole Participant becomes runtime player 1 regardless of its logical P1-P14 location. Always use the logical-to-runtime mapping helpers.
- The engine never runs the melee AI for a Participant slot. `AIStart`/`AIMeleeStart`/`PlayerSetDifficulty` combinations are all silently ignored (§66, four variants measured against a healthy computer control group). AI-vs-AI games must instead make every slot a real Computer and join as Observer; an observer connection cannot issue unit commands, so the beacon bridge (and with it coordinated attacks/support) is off in observer games.
- Do not reintroduce multiple external ProBots for team games. SC2 5.0.16 rejects multi-agent games larger than 1v1.
- Do not edit a generated map under `runtime/maps/` as a source file. Change the builder or the fixed-team base map and regenerate.
- Do not add map-level `Base.SC2Data/GameData/RaceData.xml`.
- Do not set `c_playerPropSuppliesLimit` at runtime. Both approaches have caused missing or duplicated starting units.
- The 800 supply ceiling (user-set in §68, previously 600) must remain as partial `CRace` overrides inside the existing map `UnitData.xml`.
- Never cap or freeze army production (user directive, §68): `AISetStock` army targets are the ratio tables × `STOCK_SQUEEZE_MULTIPLIER` (unreachable on purpose, so the melee AI produces to the supply ceiling), and the old `saveForExpansion` production freeze must stay removed — `verify()` fails the build if the identifier reappears. Attack-timing stock sidecar stays at 1× (readiness is clamped by `MAX_ATTACK_POWER` anyway). The same rule now covers P15 (§86): the wild-Zerg `armyTarget` cap is deleted and `verify()` fails the build if the identifier reappears anywhere in `MapScript.galaxy` — including in a comment. Its per-nest army training must stay unbounded, gated only by tech, the `reserve` mineral floor (a spending-order rule, not a count cap), and the engine's own cost/supply validation. Worker training must stay **before** the army block and **outside** any else-if chain with it: unbounded army training in a chain never reaches the worker branch, and a nest that loses its miners eventually cannot produce army either.
- Expansion attempts that fail the 90s check blacklist their target area (4 most recent per player, 300s, radius 15) so the next cycle picks a different free mineral cluster; a null candidate sets the 180s backoff instead of looping. Both exist because the nearest-free-cluster picker otherwise retries one doomed spot forever (§68, user-observed worker trains).
- Preserve user map edits unless the requested change explicitly replaces them.
- Campaign additions and Protoss faction replacements are surgical catalog snippets under `tools/campaign_data/`; never add full story dependencies.
- New campaign unit IDs are purchased by Galaxy because Blizzard melee AI ignores unknown IDs. Preserve real resource/supply/tech checks and producer cooldowns.
- A campaign purchase's `customValue` is a unit storage slot index stamped on the *producing structure*, so it must be unique per unit type, never per producer type. Two entries sharing an index share one cooldown on every structure they have in common and silently throttle each other; Goliath and Predator both shipped as 21. Slots 26, 30 (§70 mission hold), and 31 (script-control release) are taken. `verifyPurchaseCooldownSlots()` enforces this.
- Units on a defense/support mission (unit custom value 30 = hold-until time, §70) must stay skipped by the opcode 10/11 attack broadcasts; without that skip the 45s attack cadence overwrites every support march and defense order (`c_orderQueueReplace` on the whole ground army), which is exactly the user-observed "nobody ever helps". The support dispatcher must never reintroduce the blanket "damaged this tick" helper exclusion — in a late-game 7v7 that excludes everyone; only helpers whose own town hall is being hit are excluded, and two helpers go per critical threat.
- The map-side home-defense trigger (`gt_sc2team_HomeDefense`, §70) registers only for real-game bridges (`strategy_bridge && !bridge_probe`), never commands the human slot, and bakes team membership as build-time literals (`sc2team_PlayerTeam`). `verify()` enforces all three.
- Infrastructure/tech structures are rebuilt by explicit `AIBuild` reorders whenever their count drops below target (§71): `AISetStock` alone is nondeterministically ignored by the melee AI (Ultralisk Cavern precedent; live-game evidence: P3 rebuilt, P4 never did). `random_ground` slots with a fixed race use `RANDOM_INFRA_BY_RACE`.
- An unmet-prerequisite `AIBuild` is NOT a silent no-op: issued every tick before the melee plan has built that structure once, it permanently stalls the player's build manager — measured in §83 (every slot with an invalid opening order produced zero workers/army/expansions for 20 game-minutes; the v1.15.1 control was healthy). Every rebuild order therefore needs the per-player `gv_sc2team_InfraSeen` latch (structure completed once) AND an any-of `REBUILD_PREREQUISITE` gate listing every morph state of the prerequisite (SupplyDepot/SupplyDepotLowered, Hatchery/Lair/Hive, Gateway/WarpGate, CC/Orbital/PF). `SAFE_OPENING_AIBUILD` (Engineering Bay, Armory — §81) may skip the latch but never the gate. Never reintroduce an ungated or latch-free `AIBuild`.
- Campaign purchases must keep the bank reserve (minerals ≥ cost + 500, gas ≥ cost + 400, rechecked after **every** buy — §87 made purchases multi-buy) and the lowest-ratio-first bank claim. Without the reserve the 15s purchase tick skims the bank before the melee AI can save for tech labs, Armory, workers, or expansions, and a slot that loses the early worker race locks into permanent poverty (§61: P5 bought 49 Predators and built nothing else for 16 minutes). The old one-purchase-per-tick cap and the §62 cross-pool gate are deleted (§87, user directive — the cap forced 4 units/min regardless of Factory count): `verify()` fails the build if `meleeWorstRatio` reappears. Larva purchases keep a per-tick `maxCount` (purchases consume the larva, so an uncapped tick would erase the larva pool and starve Drones/Overlords); `verify()` enforces that marker too.
- Army production is driven by the §87 direct-train dispatcher, not by `AISetStock` alone: `AISetStock` requests stay (harmless, occasionally honored) but the guaranteed path is direct `UnitIssueOrder` train/warp/morph commands on completed producers every 15s tick — the same measured conclusion as §62 addons, §71 infrastructure, and §63 research. Rules the dispatcher must keep: `c_orderQueueAddToEnd` only (never replace a melee AI queue), per-producer queue cap (2 buildings / 1 larva), the same bank floors as purchases/research (skip the gas floor for gas-free units), reserve one addon-capable producer per type per tick (or §82 addon orders starve forever — they need an idle producer), leave 3 larvae unspent for melee-Zerg Drone/Overlord production, and never target the human slot. Command indexes live in `DIRECT_TRAIN_BY_UNIT` and were derived from the composed liberty→liberty-campaign→swarm→swarmmulti→voidmulti `CAbilTrain`/`CAbilWarpTrain` InfoArrays (`TrainN` → index N-1); a wrong index is a *silent* wrong-unit or no-op, so never edit one without re-deriving from the vendor layers. `verify()` binds every per-player call to the table. `random_ground` slots with a fixed race use `RANDOM_TRAIN_BY_RACE` (their per-build table is empty — without this they get zero dispatcher lines) and random_ground Terran joins the §82 bio/factory addon plans; the human-slot train ban carries the same `observer_mode` exemption as the §63 research ban (the observer probe converts the human slot to an AI, so train lines there are correct). The per-tick spend order must stay **train → purchase → research**: all three share the same bank floors, so order is priority, and putting the uncapped multi-buy purchases first drains gas to the *purchase* floor every tick, permanently starving any standard unit with a higher gas floor — measured as five mech/thor slots producing zero SiegeTanks/Thors while only the purchase-free bio_tank slot built tanks.
- **Supply headroom is `c_playerPropSuppliesMade` minus `c_playerPropSuppliesUsed`, never `c_playerPropSuppliesLimit`** (§91.10). `SuppliesLimit` is the *ceiling* the cap may rise to — on this map the CRace `FoodCeiling` of 800 — not the supply your structures currently provide. The original §88 gate read `limit < 800 && limit - used < 24`, which made both terms permanently false, so **supply support never executed once between §88 and §91**: no proactive Pylon, no proactive Supply Depot, no Orbital `SupplyDrop`. Blizzard's own test is `SuppliesUsed > SuppliesMade` (`starcoop/LibCOMU.galaxy:12962`). `verify()` fails the build if headroom is measured against `SuppliesLimit` again. The `made < ceiling` term stays — that is the real "stop spamming at max supply" guard the ceiling value is for. The same swap was in **three** places with two opposite symptoms (§91.11): the §88 gate and the P15 Overlord gate were permanently *closed* by it, while the campaign-purchase affordability check (`used + cost > limit`) was permanently *open* — that one let purchased units ignore supply entirely, measured as a `mech_macro` slot running **266 army at 700 supply off three Supply Depots** (250 of them Goliaths/Predators; the 16 rule-abiding units were the whole rest). The user-reported "Terran 400 vs Protoss 60–80" was that bypass, not race balance. In non-comment code `c_playerPropSuppliesLimit` may now be read **exactly once** — the `made < ceiling` guard — and `verify()` counts the occurrences; affordability and headroom both use `SuppliesMade`.
- Diagnose a silent gate by **bypassing it in an experimental build**, not by reading the code around it. §91.10 cost two failed fixes (a direct Probe build path, then a builder cooldown stamp) that were both dead code behind a closed gate; a two-line `return true` experiment then a single-term `return limit < 800` experiment isolated the false term in two runs. This is the §89 lesson applied to control flow rather than to orders.
- Supply support (§88): the melee AI's depot/pylon construction cannot keep up with the §87 dispatcher, so custom_ai Terran slots get a proactive `AIBuild` SupplyDepot plus an Orbital Command `SupplyDrop` calldown (ability `SupplyDrop`, Execute index 0, energy 50, permanent +8 — cast once per un-buffed completed depot, at most one per player-tick), and Protoss slots get a proactive `AIBuild` Pylon. The block-detection gate (`sc2team_SupplyBlocked`: used ≥ 32, limit < 800, headroom < 24) must stay: without the used≥32 floor the orders interfere with the opening (§83 risk), and without the limit<800 ceiling they spam at max supply. Supply orders keep the §83 completed-once gate, an in-flight cap of 2, run **before** the train dispatcher (a supply-blocked tick voids every train order), and never target the human slot (observer exemption applies, same as train/research).
- P15 wild-Zerg §88 rules: (1) `sc2team_HostileWildTrainLarva` stamps larva custom value **28** with the tick time and skips already-stamped larvae — the Overlord/worker/army blocks otherwise overwrite each other's same-tick `c_orderQueueReplace` orders on the same larvae, which was the measured cause of "0 new Overlords in 20 minutes" (custom value 27 remains the raid return time). (2) Destroyed nests are rebuilt: anchor positions are remembered (initial 16 + later expansions, dedup radius 20), and a missing anchor gets the nearest Drone sent to rebuild a Hatchery — alpha (1 o'clock) first, one attempt in flight, 180s deadline then retry. (3) The alpha nest evolves like a melee AI: InfestationPit (ZergBuild 8) → Hive (`UpgradeToHive` 0) → UltraliskCavern (ZergBuild 7) → Ultralisk training (LarvaTrain 6), all engine-validated. All indexes derived from the composed liberty→swarm→swarmmulti→voidmulti layers; `verify()` binds them.
- P15 §89 (user directive: "remove every army cap, produce like crazy; only the 7-minute **attack** ban stays"): army composition caps (`desiredRoaches`/`desiredHydras`) and the roach/hydra unlock timers are **deleted** — `verify()` fails the build if either identifier reappears, same principle as `armyTarget`. Unit mix comes from a tick-rotation selector (hydra/roach/zergling every 3 ticks, alpha trains Ultralisks every other tick once a cavern exists), with every remaining larva ordered each tick. Development is decoupled from the 420 s attack truce: expansion moved out of the `active` gate to its own 240 s gate (and out of the threat-check early-return), local macro hatcheries are for **every** economy nest (2 tight anchors radius 14, alpha 5, from 120 s, placement validated over 5 candidate offsets 7-13 — an unvalidated point silently drops the order), tech-building timers are 60/120/180 s, alpha tech chain 240 s, worker top-up capped at 2/tick (the old 12/20 targets measurably starved the army: cv28 makes first-order-win, so worker refills ate the larva pool; the target itself is now 8 per resource nest — §92), overlord cap 8/tick with threshold 32, alpha spines 6, two concurrent rebuild slots picking the missing site **closest to a surviving nest** (distant rebuild marches die crossing 12 AI armies; builder stamped cv29). Do not reintroduce composition targets, unlock timers, or an expansion-attack coupling for P15.
- **P15 army stops at 400 supply** (§92, user directive: "저그가 진짜 물량을 말도안되게 뽑던데 … 병력 상한을 둔다. 인구 400을 상한으로 두겠다"). This is the user reversing their own §89 "no caps at all" directive after §90 finally made P15 production work, so the two are not in conflict — §89's problem was P15 producing *nothing*. The cap is a single player-wide term on the army training block (`PlayerGetPropertyInt(15, c_playerPropSuppliesUsed) < 400`) and `verify()` requires that exact marker. Three properties must hold: it gates **army only** (workers, Overlords, and construction keep running, or a P15 that hits the ceiling and then loses its army has no economy left to rebuild with — a ceiling, not the §68 production freeze); it is measured on `SuppliesUsed`, never `SuppliesLimit` (800, meaningless here) or `SuppliesMade` (fluctuates with Overlord count) per §91.11; and it stays player-wide, so the per-nest `armyTarget` and the composition caps remain banned — those distorted the per-nest production split, which this does not. Two companion limits from the same directive: worker target is **8 per resource nest** (no alpha special case — P15's bank is trigger-fed, so Drones are not there for income), and Overlord training stops at `SuppliesMade >= 448` (= the 400 ceiling plus the 48 headroom term). Overlords had no total cap at all, so they kept consuming larvae — one each — long after army production had stopped at the ceiling.
- **The wild Zerg (map player 15) must stay a real lobby Computer slot, never Neutral Hostile** (§90, measured over twelve probes). As Neutral Hostile it cannot train a combat unit by *any* route: on the same larvae at the same instant Drone and Overlord were valid on 59, while Zergling, Roach, Hydralisk, Baneling, Mutalisk — and Marine (Terran), Zealot (Protoss) and a campaign unit — were valid on **0**, with 47,000 minerals, 50,000 gas, 250+ supply headroom, 94 banked larvae, and Galaxy itself counting 8 completed Spawning Pools. Drone and Overlord are exactly the two units a Zerg can make with no tech structures, so the engine treats P15 as permanently structure-less. This is *not* the button `Requirements` attribute: a custom `LarvaTrain` entry with the attribute deleted was refused just the same, as was a Hatchery-side `CAbilTrain`. `TechTreeUnitAllow`/`TechTreeAbilityAllow` both report allowed, `TechTreeUnitCount` sees the Spawning Pools, and `TechTreeRestrictionsEnable` changes nothing in either direction. The fix is structural — `patchPlayers` sets MapInfo player 15 `control` to 1 and `patchWildZergStart` moves a spare `StartLoc` onto the alpha nest (the P15 Lair, 1 o'clock), and `player_setups` appends the matching Computer entry. **Both halves are required**: promotion without a start point leaves the melee AI unable to build a Spawning Pool for eight measured minutes. Measured after the change (6 game-minutes, same config): Roach +28, Hydralisk +11, Zergling +7, Spawning Pools 2→11, eggs continuously 5–11; before it, army did not move from 31/55/21 at all. `verify()` fails the build if the promotion, the start point, or its position on the alpha nest is missing.
- **Turning the wild Zerg off means undoing the §90 promotion, not just emptying the trigger** (§93, launcher checkbox `wild_zerg`, default on). A promoted P15 has two brains: our Galaxy controller *and* Blizzard's melee AI, which already demonstrably picks its own main base and sets its own Hatchery rallies (§90.7/§90.13). Removing only the first leaves the second producing. So `wild_zerg=false` skips `patchWildZergStart`, leaves MapInfo player 15 `control` at its original neutral-hostile value, and omits the P15 entry from `player_setups` — all three together, or the setup count no longer matches the playable map slots. That also restores the §90 measurement as a second line of defence: as Neutral Hostile the engine refuses every combat unit on the same larvae where Drone and Overlord are valid. The map then gets `hostile_wild_idle.galaxy`, whose only order is `DroneHarvest` on drones that have no order (§89.6 rules kept: never re-order a mining drone, rotate mineral patches by index). `verify()` checks this both ways — with the flag off it fails the build if `control === 1` survives, or if any of `HOSTILE_WILD_IDLE_BANNED` (TrainLarva/BuildEconomy/TryExpand/TryRaid/`LarvaTrain`/`ZergBuild`/`TechTree*Allow(15,`/`PlayerModifyPropertyInt(15,`) is still in `MapScript.galaxy`. Never add a `TechTree*Allow` call to the idle controller: those exist to *open* production for a neutral-hostile P15 (§88), so they are the exact opposite of what this mode wants.
- **Never produce P15 army with `UnitCreate`** (user directive, §89.14: "직접 생산도 아니고 — 롤백하라"). Replacing a Larva with a finished unit skips the egg and the hatch time, so it is substitution, not production, however honestly it deducts cost. `verify()` fails the build if `sc2team_HostileWildForceSpawn` reappears. Army comes from `LarvaTrain` at the §85.6 engine-verified indices (Zergling 1, Hydralisk 3, Ultralisk 6, Roach 9).
- Do not "fix" a P15 production problem by reading the code. That path reports no error at all — `UnitOrderIsValid` simply returns false and the order is silently skipped — and reasoning from the source produced five consecutive wrong diagnoses (§89.5–89.12: bank starvation, trigger operation limit, supply block, larva contention, and the `Requirements` attribute; every one refuted by measurement). Probe what the engine actually rejects, with a control unit measured on the same larvae at the same instant. Marker-unit channels must be encoded as **counts of distinct unit types**, not positions or facings: `UnitCreate` relocates units off unplaceable ground and beacon actors force their own facing, which silently corrupted two earlier probe designs.
- P15 keeps a per-tick bank top-up (minerals and gas). The reason is not that the one-time 50,000 grant fails — it works, measured — but that uncapped production spends over 10,000 minerals a minute. Now that P15 is a real lobby slot (§90) it also mines normally; the top-up stays because the sixteen nests still outspend one base's income.
- P15 order hygiene (§89.6): never re-issue harvest to a drone that already has an order — the old code drove every nearby drone onto the single nearest mineral patch every tick (user-observed clumping) and cancelled any drone walking to a build site. Only idle drones are assigned, spread across patches by index. Construction orders stamp the builder with custom value 29 for 45 s and the nest issues no new construction until it expires; without it the structure does not exist while the builder walks, so the same condition re-fires each tick and the drone wanders forever. Watch trigger cost: P15 runs every 10 s over every nest, and a Galaxy trigger that exceeds its operation budget aborts mid-run, silently taking the whole nest-management loop (all production) with it — no full-map scan inside a per-nest or per-unit loop.
- P15 truce integrity (§89.9): defensive response uses attack-move, which chases acquired targets, so a fleeing scout worker will lead the garrison to an enemy main. Every defensive order must stamp a return time on custom value 27 (15 s during the truce, 30 s after), and `sc2team_HostileWildLeashStrays` must keep running before 420 s to send home any combat unit not stamped as home this tick (custom value 24, written by `HomeCount`). The truce blocks proactive attacks only — production, construction, expansion, and defensive response all continue.
- **The production trigger processes one player per fire, not all of them** (§95). `sc2team_ProductionSteering_Func` used to run every custom AI's economy/production/purchase/research in a single 15s call — 1,121 full-map `UnitGroup` creations per fire on the release 12-AI config, 365 of them unconditional, all synchronous on the SC2 simulation thread. That is the user-reported periodic freeze (measured worst stall 1,637 ms). Each player now has its own `sc2team_SteerP<N>()` and the trigger period is `12 / <player count>` so one full cycle is always 12 game seconds regardless of slot count — a fixed 1s period would make a 2-player game run each player 7.5× more often than before and silently change production and research rates. Each turn begins with `sc2team_RefreshCounts(player)`, one pass that tallies every type into `gv_sc2team_CountAll`/`CountDone`; the five public `sc2team_Count*` helpers and `sc2team_EconomyWorkerTarget` read those arrays. **Every accessor must keep its `*Live` full-scan fallback** for an unready cache or a type missing from the build-time table — a silent 0 there is the §83/§91.10 failure mode, and `verify()` counts the fallback paths per accessor because a guard that only checked "the string appears somewhere" missed deleting one of the two. Galaxy needs declaration before use, so `sc2team_TryBuildTerranAddon` and `sc2team_EconomyWorkerTarget` sit after the cache accessors.
- **Expanding requires raising the town-hall produce cap, not just allowing the unit** (§96). Two independent lines blocked every expansion from §68 until §96: the branch's `TechTreeUnitAllow(..., true)` was overwritten three lines later by the unconditional `TechTreeUnitAllow(..., canExpand)` (false unless all town halls are dead, or rich Zerg), and `townHallCap` was set to `sc2team_CountAllProduction(player, <hall>)` — the count you already have, so "one more" was never permitted, dropping to 0 once a Command Center morphed to an Orbital or a Hatchery to a Lair. Measured: 13 slots stuck at one base for a whole 8-minute run; after the fix every slot passed two bases and four reached three, matching the §60 timings. Grant expansion by setting `canExpand = true` **and** `townHallCap = townHallTypeCount + 1` inside the branch, and call `TechTreeUnitAllow` exactly once — "once" is the part that matters here; §98 then moved that single call to *before* the direct build order, so do not read this as "at the end". `verify()` fails the build if a branch calls `TechTreeUnitAllow(..., true)` directly or if the `+ 1` cap raise disappears. The 5-base ceiling (`expandBlocked`) is the intended limit and only became reachable after this fix. Note `productionReady` and `workersShort` are still computed every tick and read nowhere, and §60's escort-before-expand survives only as a comment — restoring it needs the banned `sc2team_NextExpansionPoint`, so it is a user decision, not a cleanup.
- **The expansion allowance must be applied before the direct build order** (§98). `sc2team_TryBuildExpansionAt` picks its worker with `UnitOrderIsValid`, which resolves *immediately*, so emitting `TechTreeUnitAllow`/`TechTreeSetProduceCap` after it means the check always sees the previous tick's "town hall forbidden" state: the direct build never fires, while `townHallCap + 1` still opens and the melee AI spends it beside its own main. That is the measured cause of the user-reported "expansion is weak but a second and third Nexus keep appearing at the main" — 10 new town halls with 7 on-candidate before the fix, 31–37 with 30–35 on-candidate after. The identical ordering was harmless in the pre-§97 `AIExpand` path because that is an *asynchronous* request, so a marker-presence check cannot catch this regression; `verify()` compares the two positions inside each slot's steer function and fails the build if the allowance comes last. Expansion is also two-stage: the builder gets a move order with the cap **closed**, and the allowance opens only once it is within 6 of the target (`sc2team_TryStageExpansionWorker` → `sc2team_ExpansionBuilderAtTarget`), because the window otherwise equals the walk and this map's expansions run 56–204 away. Never raise `townHallCap` during the move stage, never gate the move stage's cancel on `UnitOrderCount > 0` (arriving *is* zero orders — that inverted test cut expansions 37→12), and stamp the staged worker with cv22 as well as cv20 or `sc2team_ReleaseEconomyHarvestWorkers` never returns script control. The duplicate block tests Voronoi attribution **first** and only then a 10.0 crowding radius; 14.0 permanently closed candidate 34, a legitimate separate base 13.15 from P12's start hall. A residual 1–2 melee-AI town halls per game remain by user decision — the produce cap is inherently shared with the melee AI.
- Terran addons are attached structures, so `AIBuild` cannot create them and `AISetStock` can be ignored. §82 directly orders only completed, idle, placement-valid producers with their native `*AddOns` ability, at most once per player per 15-second tick. Bio receives one Barracks Tech Lab then reactors; tank/mech factories receive Tech Labs; enabled support air receives one Starport Tech Lab. Never replace a busy production queue to add an addon.
- A roster unit hidden from a command card is usually an unmet `Requirements`, not a broken button: SC2 hides such buttons rather than disabling them. Goliath needs `HaveArmory`, Medic needs `HaveAttachedTechLab`; Predator has no requirement and is the control for "is the card wired at all".
- The other way a card button vanishes is a slot collision with the *final melee* layout, not the liberty base layout: voidmulti moves the SiegeTank button to Factory (0,3), and when two valid buttons share a slot only the lower index shows. Goliath lives at (1,2); check the composed liberty→swarm→voidmulti card before placing any new button. Sharing with construction-only buttons (SelectBuilder at (1,3)) is safe.
- Melee weapon/armor upgrades reference effects and units by id, so a new roster unit gets no upgrade benefit and no +N display until `roster/UpgradeData.xml` appends its references (Effect Amount, Weapon Level + per-level Icon, Unit LifeArmor/LifeArmorLevel) to the melee CUpgrade records. Weapons also need their own level-0 `Icon` or the info-panel weapon slot is blank. The same applies to a Protoss faction that swaps a unit's weapon to a new damage effect (§67 Aiur: Zealot, Dragoon, Whirlwind — fixed via `protoss/aiur/UpgradeData.xml`); armor/shield upgrades keyed on the unchanged unit id keep working, which is the telltale symptom.
- A `CAttachMethodPattern` is driven by its `Driver` — the *launch effect id*. Reusing Blizzard's `AMPatternGoliath` (Driver `GoliathALM`) with a different launch effect silently resolves nothing and missiles spawn at the unit origin (the pelvis, user-observed). Clone the pattern per launch effect (Blizzard does: `AMPatternSpartanCompany`) and keep `Fallback="SetB"` on the action's `LaunchAttachQuery` like the co-op goliath.
- AI weapon/armor **and tech** upgrades come from the §63/§69 research trigger: direct `UnitIssueOrder` research orders on idle research structures, one per player per 15s tick, with `TechTreeUpgradeCount` queued-or-better dedup, a previous-level gate, an optional `prerequisiteStructure` gate (§69: empty = ignore, "Lair" also satisfied by Hive — needed because the function returns true even on an engine-rejected unmet-requirement order and would otherwise starve later ladder entries), and the same bank reserve as purchases (minerals ≥ cost + 500, gas ≥ cost + 400). Tech-upgrade ability-command indices come from the composed liberty→swarm→swarmmulti→voidmulti `CAbilResearch` InfoArrays (`ResearchN` → index N-1) in `vendor/sc2gamedata-source`; the Protoss faction is threaded to the ladder so Aiur drops Blink but keeps Charge. The melee AI does not research here on its own, and `AISetStock` requests are not a substitute (§62 addon precedent). Never emit research lines for the human slot without the `research_probe` flag; `verify()` enforces both.
- The research trigger's bank reserve is deliberately **smaller** than the purchase/train reserve (§91: minerals ≥ cost + 150, gas ≥ cost + 100). It must not be raised back to the purchase floor: the per-tick spend order is train → purchase → research, the train dispatcher drains the bank to *its* floor (Marauder gas 25 + 400 = 425), and the old research floor was higher (100 + 400 = 500), so research could never fire — measured as five custom_ai Terran slots at 0–1 upgrade levels after 16 game-minutes while a pure melee-AI control slot was equal or better, with bio_tank holding an Engineering Bay from the two-minute mark and zero infantry upgrades at sixteen. The §61 bank-drain that motivated the large reserve was caused by *uncapped multi-buy purchases*; research is hard-capped at one per player per tick, so it cannot reproduce it.
- Terran research ladders put tech upgrades (Stimpack/Combat Shield/Concussive, Infernal Pre-igniter, Mag-Field Accelerator) **before** the weapon/armour ladder (§91). The ladder issues one research per player-tick and weapon/armour levels are serialised by their previous-level gate, so tech placed behind twelve weapon/armour entries is never even attempted. A ladder entry whose research structure does not exist returns false and falls through, so a missing Tech Lab costs nothing.
- Adding a structure to `SAFE_OPENING_AIBUILD` waives the "completed once" latch, which makes it a **turn-zero** order — so its `REBUILD_PREREQUISITE` must be a structure that appears *after* the opening, not one that always exists. §91 added Forge with prerequisite `Nexus` and measured the result: at six minutes every Protoss slot had a Forge, **no Cybernetics Core, and zero army** (control: no Forge, a Cybernetics Core, 4–14 army). The prerequisite is now `CyberneticsCore` (and Evolution Chamber's is `SpawningPool`). This is the mild form of §83 — the build manager is not stalled, only reordered — but it cost the whole Protoss team its early army.
- Cyclone is `FactoryTrain` command index 7 (InfoArray `Train8`), 150/100, supply 3, with the Mag-Field Accelerator (`CycloneLockOnDamageUpgrade`) at `FactoryTechLabResearch` index 9. It is in the three mech builds and random_ground Terran, deliberately not in `bio_tank` (2–3 Factories there would make it compete with Siege Tanks). Engine-verified against a Siege Tank/Thor control: a wrong train index is a silent no-op, so never change it without re-deriving from the vendor layers and re-counting the units on the field.
- The running game reads its dependency list from the map's `DocumentHeader`, not `DocumentInfo`. Patch both or the dependency silently does nothing.
- Keep the campaign dependency list minimal. Adding Swarm Story pulls in `Campaigns/Swarm.SC2Campaign`, which steals the `FactoryTrain` `Train20` slot the Goliath purchase uses and stops the launcher from starting.
- A roster `CActorUnit` must parent from a `Generic*` base actor and set its own `unitName`. Parenting from a concrete unit actor bakes in the parent's `UnitBirth` token, so the actor never binds and the unit is a gray sphere.
- A `CModel` `parent` does not inherit the `Model` asset path; every roster `CModel` states its own `.m3` path.
- Catalog, debug-create, and combat probes all pass while a unit renders as a gray sphere. Only `verification/verify_campaign_render.py` (or opening the game) can tell. Never call a model or actor change verified without looking at a rendered frame.
- A roster `CUnit` parents from Blizzard's own campaign record, never from a melee lookalike. `HellionTank` carries `MorphToHellion`, and a melee parent's radii and `LifeArmorName` do not match a campaign model. Delete any stat that equals the original instead of restating it.
- SC2 links a unit actor's voice by actor id: actor `Predator` finds `CSound` `Predator_What` with no XML. Roster actors are named `SC2Team*`, so that auto-link finds nothing and every roster unit is mute unless its `SoundArray` names Blizzard's `CSound` explicitly. A wrong sound id is silent, not fatal.
- Weapon fire and impact sounds come from `CActorAction`, and its `effectAttack` must name the `CEffectDamage` leaf, never the weapon and never the `CEffectSet` wrapping it.
- A `CButton` is an icon and nothing else, including Blizzard's own. Hotkeys come from `Button/Hotkey/<id>` in `GameHotkeys.txt` and text from `Button/Name|Tooltip/<id>` in `GameStrings.txt`. Write every `_NRS`/`_SC1`/`_USD`/`_USDL` profile variant or the hotkey works only on the default profile.
- Only name sounds from the base game or the Liberty campaign. The `Aberration_*` voice set exists solely in Swarm Story, which is the dependency that breaks Goliath production.
- When a probe places subjects at different map positions, it measures the terrain as much as the units: an unpathable spot fails whatever is put there. Run every subject at one shared spot.
- Close SC2 and the SC2 Editor before engine verification when possible; stale processes and fixed API ports can invalidate a test.
- Test mode forces `full_vision`, which is baked in at map build time, so it must keep building to its own `-test` map file and never overwrite the release map. It must also not write the forced value back into the user's saved settings.
- `all_resources` is a one-off 5000/5000 grant, not an unlimited state; repeated grants stack, and that is the only reason the test launcher's infinite resources work. `minerals`/`gas` individually are unreliable — measured gas did not move. `fast_build` makes structures instant but units only about 17x faster.

## Minimum verification before handoff

Follow [`docs/verify/verification-guide.md`](docs/verify/verification-guide.md). At minimum run the offline test tier. For map, Galaxy, strategy, economy, start-unit, or supply changes, also run the applicable SC2 engine test and record the result in `HANDOFF.md` and `docs/latest_status.md`.

Deterministic harness: `.\.venv\Scripts\python.exe verification\verify_all.py --tier offline` runs the reproducible offline tier (unit tests, syntax, and per-fixture builder structural verification) against checked-in fixtures in `tests/fixtures/`, independent of the mutable `runtime/custom_ai_settings.json`. `--tier short-engine` runs the two SC2 probes, `--tier release-engine` opens the versioned map with the saved configuration, and `--tier long-engine` reports the five Tier-4 checks that still lack retained runners. Engine tiers need SC2/Editor closed first. `--list` / `--emit-fixtures` are available for inspection.
