# V2 현재 상태 (2026-07-23)

실측으로 확정된 것과 아직 모르는 것을 가른다. **여기 있는 수치는 전부 엔진
프로브 결과이고, 추론은 그렇다고 표시한다.**

---

## 1. 시간 기준 — 읽기 전에 반드시 알 것

SC2 "빠르게" 속도에서 **게임 내 시계는 16루프당 1초**로 흐른다. 초당 루프는
22.4이므로 게임 시계는 실시간의 1.4배로 간다. Galaxy의 `c_timeGame`과
`AIGetTime()`도 게임 시계를 쓴다.

초기 프로브는 `루프 / 22.4`로 "분"을 계산했다. **그래서 §3의 확장·병력 측정에
적힌 "20분"은 실제로는 게임 시계 28분이다.** A/B 비교는 양쪽이 같은 기준이라
결론은 유효하고, 절대 시각 라벨만 틀렸다.

이 오류로 "9분 해제"가 8분에 일어난 것처럼 보인 적이 있다. 이후 프로브는
`루프 / 16`으로 고쳤다(`v2/verification/probe_wild_zerg.py`).

---

## 2. 실험 설계 — 홀짝 뒤집기

7v7 구성에서 런타임 슬롯을 홀/짝으로 갈라 한쪽에만 손잡이를 걸고, **같은 판
안에서** 대조한다. 그리고 **패리티를 뒤집어 한 판 더** 돌린다.

**뒤집기가 없으면 판정이 틀린다.** 짝수 슬롯은 종족 구성이 달라(저그 2 vs 1)
병력 보급값이 구조적으로 높다. 8분 이후 10/10 비교에서 짝수가 이겼고, 이
편향을 다이얼 효과로 오독한 적이 있다.

판정: **양쪽 패리티 모두에서 다이얼 쪽이 이겨야** 진짜다.

## 3. 검증된 것

### 3.1 확장 보조 — `AIExpand`

좌표를 주지 않는다. "본진에서부터 찾아서 확장해라"만 요청하고 위치는 밀레
AI가 정한다. 무작위 종족을 위해 `PlayerRace()`로 런타임에 타운홀 종류를 고른다.

| 구성 | 기지 | 생산건물 | 일꾼 |
| --- | --- | --- | --- |
| 순수 밀레 AI (기준선, 2회 재현) | 1.2 | 4.3 | 35.2 |
| **`AIExpand` 적용** | **2.8** | 5.0 | **55.6** |

기지 2.3배, 일꾼 1.6배. 효과가 커서 잡음에 안 묻힌다.

**V1 §97이 이 네이티브를 금지했던 이유는 "우리 좌표를 안 지킨다"였다.** V2는
좌표를 주지 않으므로 그 이유가 없다.

### 3.2 병력 보조 — `AISetStockArmyDefaultScale`

밀레 AI가 원하는 병력 목표에 배율만 건다. 유닛 종류도 조합 비율도 우리가
고르지 않는다.

| 판 | 처리 | 다이얼 | ON | OFF | 비율 |
| --- | --- | --- | --- | --- | --- |
| R5 | 배율 2.0 | 짝수 | 463 | 267 | **1.73** |
| R6 | 배율 2.0 | 홀수 | 567 | 391 | **1.45** |

양방향 통과. R6에서는 짝수 슬롯의 구조적 우위까지 뒤집었다.

시간에 따라 커진다(8분 ~1.0 → 20분 1.45~1.73). 초반을 안 건드리므로 §83류
오프닝 방해 위험이 낮다. 경제 고갈(일꾼·기지 감소)은 관측되지 않았다.

**주의**: 배율 3.0은 미검증이다. §5.1 참조.

### 3.3 야생 저그 선배치 병력 고정

P15 선배치 전투 유닛의 제어권을 밀레 AI에게서 뺏고, 지정 시각에 돌려준다.
건물·`Drone`·`Larva`·`Egg`·`Overlord`·`OverlordTransport`·`Overseer`는 제외.

**처음 자리에서 10 이상 움직인 선배치 유닛 수** (게임 시계):

| 시각 | 고정 ON | 고정 OFF |
| --- | --- | --- |
| 0.5분 | 0 / 122 | 0 / 128 |
| 1분 | **2** | **86** |
| 8.5분 | 2 / 121 | — |
| **9.5분** | **84 / 119** | — |
| 11분 | 90 / 116 | — |

끄면 1분 만에 3분의 2가 출격한다. 켜면 9분 해제까지 움직이지 않고, **9:00에
정확히 풀린다.** 본진 반경 30 안 병력이 18 → 193으로 쌓이다가 해제 직후
10으로 빠진다.

구현: 고정할 때 custom value 40에 표식을 남기고, 해제할 때 **표식이 있는 것만**
푼다. 전체 맵 스캔은 잡을 때 1회 + 풀 때 1회, 총 2회다.

## 4. 실패한 것 — 다시 시도하지 말 것

### 4.1 `AISetStockExtra` (임계값 방식)

무효. 2판. P6이 결정적 반례 — **기지 4개, 일꾼 68, 30분, 다이얼 ON**인데
생산건물이 8분 이후 3개에서 한 칸도 안 움직였다. 광물 임계 600을 못 넘겼을
리가 없다.

### 4.2 `AISetStockEx` + `c_stockForced` — 덧셈 형태 (`have + N`)

4판 측정, **재현 실패.** R1~R3은 다이얼 쪽이 이겼지만 **R4에서 뒤집혔다**
(ON 5.7 / OFF 7.2). 그것도 delta가 가장 큰 판에서. 용량을 4배 넣고 효과가
반대면 그건 효과가 아니다.

### 4.3 `AISetStockEx` + `c_stockForced` — 배율 형태 (`have × 3`)

사용자 실측 무효. 맵을 열어 주입을 확인했다 — 12명 전부 `v2_ProductionOne(N, 300)`
정확히 들어가 있었다. **"적용됐는데 효과 없음"이 확정.**

### 4.4 공통 결론

**`AISetStock` 계열로 건물을 짓게 만드는 길은 막혔다.** V1 `CLAUDE.md` §71이
이미 같은 결론을 갖고 있었다:

> 인프라/테크 건물은 명시적 `AIBuild` 재발주로 재건한다: `AISetStock`만으로는
> 밀레 AI가 **비결정적으로 무시한다** (울트라리스크 동굴 전례)

§62 부속건물, §63 연구도 같다. 이 선례를 먼저 읽었으면 3판을 아꼈다.

## 5. 미해결 문제

### 5.1 생산건물 — `AIBuild`로 전환, 미검증 ★최우선

`AISetStock` 계열이 전부 막혀서 `AIBuild` 직접 발주로 바꿨다(사용자 판단).

```galaxy
done   = AITechCount(player, what, c_techCountCompleteOnly);
queued = AITechCount(player, what, c_techCountQueuedOrBetter);
if (done < 1) { return; }                 // 이미 갖고 있는 종류만
want = done * percent / 100;
if (want <= done) { want = done + 1; }
AISetStockEx(...);                        // 무해, 가끔 반영
if (queued >= want) { return; }           // 큐 폭주 방지
AIBuild(player, c_makePriorityTown, AIGetMainTown(player), what, 1, c_nearChokePoint);
```

**해야 할 검증**
1. **T2 컴파일** — `v2/verification/smoke_v2_map.py` (생산건물 보조 켜둔 상태).
   5초에 유닛 0이면 컴파일 사망
2. **홀짝 뒤집기 2판** — 건물이 실제로 느는가
3. **§83 감시** — 다이얼 슬롯의 일꾼·기지·병력이 대조군보다 떨어지면 빌드
   매니저가 방해받은 것이다. 그 즉시 롤백

### 5.2 업그레이드를 아무도 안 한다 ★

저글링 속업, 공/방업 등 기본 업그레이드가 전혀 없다.

V1 §63이 같은 것을 관측했다 — "멜레 AI가 이 맵에서 무기/방어 연구를 전혀
하지 않는다(사용자 실관측, 전 종족)." **그런데 §63은 원인을 규명하지 않고
바로 우회로(유휴 연구 건물에 직접 `UnitIssueOrder`)를 만들었다.**

**미확인 가설**: 밀레 AI는 스톡 목록을 우선순위 순으로 처리한다. 도달 불가능한
병력 목표를 앞에 세우면 뒤쪽 업그레이드에 영영 도달하지 못할 수 있다. V1은
`STOCK_SQUEEZE_MULTIPLIER`로 일부러 도달 불가능하게 했고, **V2도 병력 배율
3.0으로 같은 모양을 만들었다.**

**가르는 실험**: 보조를 전부 끈 순수 밀레 AI로 한 판. 업그레이드가 나오면
우리 배율이 막고 있던 것이고, 안 나오면 밀레 AI가 원래 안 하는 것이다.
계측은 P1~P14 연구 건물(엔베이·아머리·포지·진화장)에 `orders`가 걸리는지로
한다 — 옵저버는 남의 업그레이드 목록을 못 읽는다.

**해결책은 원인과 무관하게 있다**: V1의 연구 트리거는 직접 명령이라 스톡
목록을 안 거친다. 명령 인덱스 표가 `tools/build/tables.cjs`에 있고, 벤더
`CAbilResearch` InfoArray에서 도출한 것이다. **잘못된 인덱스는 조용한
무동작이므로 새로 만들지 말고 그대로 가져올 것.**

### 5.3 야생 저그가 가스를 안 캔다 → 저글링·여왕만 나온다

가스가 **0인** 저그 유닛은 저글링(25/0)과 여왕(150/0) 둘뿐이다. **"여왕과
저글링만 뽑는다"는 가스 수입 0의 정확한 서명이다.** 실측에서 바퀴·히드라가
선배치분에서 하나도 안 늘었다.

**원인 확정**(사용자 실험): 밀레 AI는 기지 단위로 "광물 줄이 포화되면 추출장을
짓는다"고 판단한다. P15는 해처리 **14개**에 드론 **20기** = 기지당 1.4기라
**어느 기지도 포화 문턱에 못 닿는다.** 해처리들이 파괴되어 기지가 줄자
드론이 몰렸고, 그제서야 추출장 3개 + 가스 드론이 나왔다.

**부수 문제**: P15의 테크 건물(산란못·바퀴굴·히드라굴·스파이어·울트라리스크
동굴·진화장 2)이 **전부 1시 한 곳에 몰려 있다.** 본진이 뚫리면 테크 트리가
통째로 날아가 저글링만 남는다.

**해결은 맵 편집**(사용자 영역): 선배치 해처리를 1~2개로 줄이면 정상적인 저그
AI가 된다. 3~4개면 기지당 5~7기로 아슬아슬. 13개 유지면 지금 상태 그대로.
테크 건물은 두세 군데로 나눠 두는 것을 권한다.

### 5.4 캠페인 유닛 — 구현 완료, 엔진 미검증 ★

**해결됨(2026-07-23, 사용자 지시).** 골리앗·프레데터·의무병·애버레이션·
토라스크·랩터 진화가 V2에 들어갔다. 런처 기본값 켜짐.

사용자 지시의 핵심은 **"유닛만 가져오는 것이 아닌 업그레이드 연결 여부도 같이
가져와야 한다"** 였고, 실제로 세 덩어리가 한 묶음이라야 동작한다.

| 덩어리 | 어디서 오나 | 빠지면 |
| --- | --- | --- |
| 캠페인 의존성 | `patchCampaignAssetDependencies` + `patchDocumentHeaderDependencies` | 테란 3종이 회색 구체. **DocumentInfo 만 고치면 안 된다** — 실행 중인 게임은 `DocumentHeader` 를 읽는다 |
| 로스터 카탈로그 | `patchCampaignRoster` (8개 XML) | 유닛 자체가 없음 |
| **업그레이드 연결** | `roster/UpgradeData.xml` — 같은 패치 함수에 묶여 있다 | 공방업이 새 유닛에 **안 붙고** 정보창 +N 표기도 없음 |

셋 다 `campaign_units_pilot` 하나로 켜지고, 이 플래그는 `melee_only` 와
**독립**이다(V1 빌더 확인). 즉 V1 의 주기 트리거는 여전히 하나도 안 들어온다.

업그레이드 연결의 실측(빌드 산출물 검사): `roster/UpgradeData.xml` 이 멜레
CUpgrade 16종에 참조를 덧붙인다 — 테란 차량 공격 1~3 / 차량·함선 방어 1~3
(골리앗·프레데터), 테란 보병 방어 1~3 (의무병), 저그 근접 공격 1~3 / 지상
방어 1~3 (애버레이션·토라스크). 산출 맵의 `UpgradeData.xml` 안 `SC2Team*`
참조 **73개** 확인.

**생산은 V1 과 다르게 만들었다.** V1 은 `UnitCreate` **구매**였고, V2 는 로스터가
실제로 갖고 있는 `CAbilTrain` 슬롯에 **진짜 훈련 명령**을 낸다.

이유는 §91.11 이다. 구매는 유닛을 그 자리에 만들어 내므로 보급을 우회했고,
보급고 3개(공급량 54)짜리 슬롯이 인구 700 에 병력 266기 — 그중 250기가
골리앗·프레데터 — 를 굴린 것이 실측됐다. 사용자가 본 "테란 400 vs 프로토스
60~80"이 종족 밸런스가 아니라 한쪽만 보급 규칙을 우회한 결과였다. 훈련 명령은
비용·보급·선행조건·건설시간·알 낳는 시간을 **전부 엔진이** 검사하므로 그 우회가
구조적으로 불가능하다. 덤으로 §89.14("직접 생산도 아니고 — 롤백하라")의 치환
문제도, 쿨다운 슬롯 중복 금지(customValue 표)도 통째로 사라진다.

커맨드 인덱스는 **우리가 소유한** `tools/campaign_data/roster/AbilData.xml`
에서 그대로 나온다(TrainN → N-1). 벤더 레이어 재유도가 필요한 V1 §87 표와 달리
근거가 저장소 안 30줄짜리 파일이다. 인덱스를 바꿀 일이 있으면 **그 파일과 같이**
바꿀 것 — 한쪽만 바꾸면 조용한 무동작이다.

| 유닛 | 생산자 | 선행 | 능력·인덱스 | 비용 |
| --- | --- | --- | --- | --- |
| 골리앗 | Factory | Armory | `FactoryTrain` 19 | 150/50 |
| 프레데터 | Factory | Factory | `FactoryTrain` 20 | 100/100 |
| 의무병 | Barracks | BarracksTechLab | `BarracksTrain` 19 | 75/50 |
| 토라스크 | Larva | UltraliskCavern | `LarvaTrain` 16 | 300/200 |
| 애버레이션 | Larva | InfestationPit | `LarvaTrain` 27 | 200/75 |
| 랩터 진화 | SpawningPool | Lair 또는 Hive | `SpawningPoolResearch` 9 | 100/100 |

밀레 AI 를 방해하지 않기 위한 제약(전부 V1 §87 훈련 디스패처와 같은 값):
`c_orderQueueAddToEnd` 만 — 대기열을 절대 교체하지 않는다 · 건물 대기열 2,
라바는 유휴만 · 라바 3기는 남긴다(밀레 저그의 드론·대군주용) · 잔고 하한
광물 cost+500 / 가스 cost+400 · 틱당 건물 2기, 라바 1기 · 15초 주기.

**빌드 시점이 아니라 런타임에 해금한다.** V1 은 `TechTreeUnitAllow` /
`TechTreeUpgradeAddLevel(HotSTorrasque)` 를 빌드 시점의 **설정된 종족**으로
깔았다. 그런데 V2 런처 기본 설정은 여덟 슬롯이 전부 Random 이라 빌드 시점에는
종족을 알 수 없고, 그러면 **한 줄도 안 깔린다** — 궁극탑을 지어도 토라스크
명령이 조용히 무효가 된다. 이 구멍은 산출물 검사에서 실제로 잡혔다(첫 빌드에서
토라스크 부여 0줄). `v2_UnlockCampaign(player, PlayerRace(player))` 이 플레이어당
한 번 돌며 런타임 종족으로 해금한다.

**아직 안 한 것: 엔진 검증.** 훈련 인덱스가 틀리면 **오류가 아니라 무동작**이다.
켜고 한 판 돌려 유닛이 실제로 나오는지 세야 한다(§5.1 의 생산건물 검증과 같은
판에서 같이 볼 수 있다). 안 나오면 의심 순서는 (1) 잔고 하한이 너무 높다
— 토라스크는 광물 800/가스 600 이 필요하다, (2) 대기열 상한 2 라 밀레 AI 가
공장을 계속 점유한다, (3) 인덱스. **셋 다 코드를 읽어서 고르지 말고 하나씩
풀어 보는 방식으로 가를 것**(§91.10 의 교훈).

### 5.5 유닛 금지가 없다 (§104의 (c))

V2에는 유닛 종류를 막는 코드가 없다. 밀레 AI가 밴시·바이킹·공허 포격기를
자유롭게 뽑는다. V1은 생산 규칙에서 지상군만 요청하는 방식으로 배제했는데,
V2는 그 규칙 자체가 없다.

**미결.** 넣는다면 `TechTreeUnitAllow(player, <type>, false)`이고, 막았을 때
밀레 AI가 그 자원을 지상군에 쓰는지 아니면 §83처럼 멈추는지 실측이 필요하다.

### 5.6 죽은 체크박스 — "수송·탐지 지원 공중 유닛 허용"

`allow_support_air`는 `production.cjs` 안에서만 살아 있는데 `melee_only`는 그
파일을 건너뛴다. **V2에서 켜든 끄든 맵이 한 바이트도 안 바뀐다.** V1 UI를
그대로 옮기다 남긴 것. 제거하거나 비활성 표시할 것.

### 5.7 P15는 보조를 하나도 안 받는다

`assist_players()`가 "사람 슬롯 + 커스텀 AI 슬롯"만 잡아서 야생 저그는 확장
보조도 병력 배율도 안 걸린다. 의도한 설계는 아니고 범위를 좁게 잡은 결과다.
사용자 판단: **그대로 둔다** (P15가 이미 충분히 강함).

## 6. 성능

트리거 비용은 V1과 **종류가 다르다.**

| 호출 | 맵 스캔 |
| --- | --- |
| `AIGetNumEstablishedTowns` / `AIHasNearbyOpenExpansion` / `AIExpand` | 없음 |
| `AITechCount` / `AISetStockEx` / `AISetStockArmyDefaultScale` / `AIBuild` | 없음 |

`UnitGroup` 생성 0, `RegionEntireMap()` 주기 호출 0, 유닛 순회 0. §95에서
1,637ms 정지를 일으킨 것은 15초마다 1,121회의 전체 맵 `UnitGroup` 생성이었다.

예외: 야생 저그 고정이 전체 맵 스캔을 쓰지만 **총 2회**(잡을 때·풀 때)다.

**아직 안 쟀다.** 위는 원시연산으로부터의 추론이다. §95도 "이 정도면 괜찮겠지"로
3버전을 갔다가 실측에서 1,637ms가 나온 사례다. 방향이 확정되면 §95 방식으로
프레임 정지 시간을 A/B 실측할 것.

**별개 비용**: 병력 배율 2배는 유닛 수를 늘리므로 경로탐색·충돌 비용이 실제로
늘어난다. 이건 최적화 대상이 아니라 원하는 결과의 대가다.

## 8. 이번에 고친 V1 버그

**야생 저그 시작 위치가 1시가 아니라 3시로 끌려가던 문제** (`tools/build/archive.cjs`).

`patchWildZergStart`는 "P15 타운홀 5.0 이내"의 여분 StartLoc만 사용자 배치로
인정했다. 그런데 1시 StartLoc(237.5, 240.5)에서 가장 가까운 P15 해처리
(235.5, 232.5)까지가 **8.25**라 탈락했고, 폴백이 그 점을 Lair 좌표인 3시
(242.5, 120.5)로 옮겼다. §90.12가 고치려던 증상이 반경 때문에 그대로 재현됐다.

`verify()`도 못 잡았다 — 옮긴 뒤 거리가 0이 되니 통과했다. 검사가 "사용자
배치가 살아남았는가"가 아니라 "결과가 타운홀 위인가"만 봤다.

**수정**: 반경 5.0 → 10.0, 여분 StartLoc을 "문서상 첫 번째"가 아니라 "가장
가까운 것"으로 선택, 상수를 `verify.cjs`가 import하도록 변경(두 곳에 숫자를
따로 두면 조용히 어긋난다).

**이것은 V1 빌더 수정이다.** 야생 저그를 켠 설정으로 V1을 다시 빌드하면
바이트가 달라진다. 의도한 변경이다.
