# V2 검증 하네스 구조

V1의 가장 큰 자산은 코드가 아니라 **검증 장치**다. V1 하네스는 잘 작동했고
(offline 12/12, 픽스처, 바이트 동일 오라클), V2는 그 구조를 가져오되
**V1이 못 잡은 두 부류를 새로 잡는다.**

## V1 하네스가 놓친 것 (이번에 실제로 터진 것들)

| 놓친 것 | 사고 |
| --- | --- |
| **Galaxy를 컴파일하지 않음** | 미선언 상수 `c_unitPropMax` 하나로 맵 스크립트 전체가 침묵 사망. offline 12/12는 그대로 통과했고, 엔진 프로브에서야 "비컨 0개"로 드러났다 |
| **데이터 파일 출처 검사 없음** | `expansion-layout.json`이 베이스 맵보다 20시간 낡았는데 아무도 몰랐다. 광물을 옮긴 뒤에도 옛 좌표를 계속 실어 날랐다 |
| **문자열 존재만 검사** | 게이트가 붙었는지, 순서가 맞는지 안 봤다. §98 순서 회귀와 감사 B2/B3/B4가 전부 이 구멍 |

## 티어 구조

V1의 4티어를 유지한다. 실행 비용 순이고, 위로 갈수록 SC2가 필요하다.

### T0 — 정적 (SC2 불필요, 초 단위)

- 파이썬 문법·타입
- JS 문법 (`node --check`)
- **데이터 무결성**: 모든 생성 데이터 파일의 `source_map` 해시가 현재
  베이스 맵과 일치하는가. 불일치면 즉시 실패 (V1에 없던 것)
- 단위 테스트

### T1 — 구조 빌드 (SC2 불필요, 분 단위)

체크인된 픽스처(`v2/tests/fixtures/*.json`)로 맵을 굽고 산출물을 검사한다.

- 빌드 성공
- **구조 검사**: 마커 문자열이 아니라 함수 본문을 잘라서 검사.
  예 — "이 함수 본문에 `RegionEntireMap()`이 없다", "허가가 발주보다 앞이다"
- **금지 primitive 검사**: `TechTreeSetProduceCap(`, `AISetStockUnitNext(`가
  산출 스크립트에 **하나라도** 있으면 실패.

  **`AIBuild`는 2026-07-22에 금지 목록에서 빠졌다.** 병력 목표를 올리면 병력은
  느는데 밀레 AI가 생산건물을 안 늘리고, 건물을 늘리는 다른 모든 길
  (`AISetStockExtra`, `c_stockForced` 덧셈·배율)이 무효로 판명됐기 때문이다
  (사용자 판단: "생산 건물만 강제하겠다"). 대신 **모양 검사**로 바꾼다:

  - `AIBuild` 호출은 반드시 `c_techCountCompleteOnly >= 1` 게이트 뒤에 있어야
    한다. 즉 **이미 완성해서 갖고 있는 종류만** 발주한다. 이것이 §83
    (전제조건 미충족 AIBuild → 빌드 매니저 영구 정지)을 구조적으로 막는다
  - 그 슬롯이 0개인 종류를 새로 짓게 하는 `AIBuild`는 여전히 실패시킨다.
    그것이 "빌드를 바꾸는 것"이고 §83의 실제 위험 구역이다
- **바이트 동일 오라클**: 순수 리팩터링은 픽스처 산출물이 한 바이트도
  움직이지 않아야 한다

### T2 — Galaxy 컴파일 (SC2 필요, 1회 기동)

**V1에 없던 티어.** 맵을 열어 스크립트가 실제로 컴파일되는지만 본다.
게임을 진행시키지 않으므로 빠르다.

미선언 식별자·오타·타입 오류를 여기서 잡는다. 하루에 두 번 당한 사고가
둘 다 T1을 무사 통과했다는 것이 이 티어를 만드는 이유다.

**증상을 알아두면 진단이 빠르다.** 스크립트가 컴파일에 실패하면
`MeleeInitUnits()`를 포함한 맵 초기화 트리거 전체가 안 돈다. 그래서
**게임 시작 5초 시점에 이미 모든 플레이어의 유닛이 0**이다(선배치 유닛과
중립 자원만 남는다). "AI가 아무것도 안 한다"가 아니라 "게임이 시작을 안 했다"에
가깝다. 반대로 트리거는 살아 있는데 동작만 없으면 시작 유닛은 정상이다 —
이 둘을 먼저 가르면 진단이 절반으로 준다.

**실제 사고 두 건**

| 코드 | 왜 죽었나 |
| --- | --- |
| `UnitGetPropertyFixed(u, c_unitPropLife, c_unitPropMax)` | `c_unitPropMax`는 존재하지 않는 상수. 최대 생명력은 `c_unitPropLifeMax, c_unitPropCurrent` |
| `unit marker;` | **`marker`는 Galaxy 내장 타입 이름**(`const marker c_noMarker = null;`). 타입 이름을 변수명으로 쓸 수 없다 |

**규칙: 예약 타입 이름을 변수명으로 쓰지 않는다.** `marker` · `wave` ·
`wavetarget` · `waveinfo` · `unit` · `unitgroup` · `point` · `region` ·
`order` · `abilcmd` · `trigger` · `timer` · `playergroup` 등. 변수는
`markerUnit`, `waveTarget` 처럼 접미사를 붙인다.

**규칙: 벤더 소스에 없는 네이티브·상수를 쓰지 않는다.** 쓰기 전에
`vendor/sc2gamedata-source`에서 선언을 확인하거나, V1 생성 코드에 이미
쓰이고 있는지 확인한다. 이름만 보고 있을 것 같아서 쓰면 스크립트가 죽는다.

판정: 맵 로드 후 우리 트리거가 만드는 표식(초기화 완료 유닛/변수)이
관측에 보이면 통과.

**시간 기준 주의.** SC2 "빠르게"에서 게임 내 시계는 **16루프당 1초**로 흐른다
(초당 루프는 22.4이므로 게임 시계는 실시간의 1.4배). Galaxy의 `c_timeGame`과
`AIGetTime()`도 게임 시계를 쓴다. 프로브가 `루프/22.4`로 "분"을 계산하면
트리거 시각과 1.4배 어긋나고, 실제로 "9분 해제"가 8분에 일어난 것처럼 보인
적이 있다. **계측 라벨은 `루프/16`으로 붙일 것.**

### T3 — 동작 계측 (SC2 필요, 게임 진행)

실제로 게임을 돌려 수치를 센다. **기능이 살아 있는지**를 보는 티어이며,
"조용히 닫힌 게이트"(§91.10 부류)를 잡는 유일한 수단이다.

기본 계측 항목:

- 슬롯별 기지 수 추이 (확장이 도는가)
- 슬롯별 보급 여유 (보급 보조가 도는가)
- 슬롯별 병력 공급값 (생산 보조가 도는가)
- 슬롯별 업그레이드 레벨 (연구 보조가 도는가)
- 금지 유닛이 실제로 0인가

**대조군 필수.** 우리 레이어를 끈 슬롯 또는 끈 판을 같이 돌려 비교한다.
절대값은 의미가 없고 대조군 대비 차이만 의미가 있다.

**홀짝 뒤집기 필수.** 런타임 슬롯을 홀/짝으로 갈라 한쪽에만 손잡이를 걸고,
**패리티를 뒤집어 한 판 더** 돌린다. 양쪽 모두에서 다이얼 쪽이 이겨야 진짜다.

이유는 측정으로 확인됐다 — 이 맵의 짝수 슬롯은 종족 구성이 달라(저그 2 vs 1)
병력 보급값이 구조적으로 높고, 8분 이후 10/10 비교에서 짝수가 이겼다. 뒤집기
없이 한 판만 보고 `c_stockForced`가 작동한다고 오판했다가 R4에서 뒤집혔다.

### T4 — 빌드 식별 계측 (SC2 필요, 조사용)

정기 실행이 아니라 **표를 채우기 위한 조사**다.

같은 종족·같은 `ai_build`로 여러 판 돌려 어떤 세부 빌드가 나오는지 센다.
`v2/docs/builds.md`의 "대응 분류(추정)" 열을 실측으로 확정하는 것이 목적.

판정 방법: 6분 시점의 생산 건물 구성과 병력 구성으로 세부 빌드를 식별한다.
(예: 관문 4 + 인공제어소 0 = 4관문 타이밍, 로보공학시설 + 불멸자 = 추적자 로보)

## 규칙

0. **계측은 절대 사용자 실행 경로에 들어가지 않는다.** 프로브가 심는 트리거·
   마커 유닛·집계 코드는 **별도 진단 맵**에만 존재한다. 사용자의 실전 런처와
   테스트 런처가 굽는 맵에는 한 줄도 들어가지 않는다. 구체적으로:
   - 진단은 별도 맵 파일(`runtime/maps/<probe-name>.SC2Map`)과 별도 설정
     파일로 굽는다. 릴리스 맵과 `runtime/custom_ai_settings.json`은 읽기만 한다.
   - 계측 코드는 저장소 본체(`tools/`, `app/`, `sc2team/`)가 아니라 프로브
     스크립트 쪽에 둔다. 빌더에 "진단 플래그"를 새로 만들지 않는다.
   - 프로브를 돌린 뒤에는 릴리스 맵에 프로브 심볼이 없는지 확인한다.
   이것은 사용자 지침이다(§101): "릴리스 맵과 설정을 변형하지 말 것,
   별도의 진단 맵·진단 설정·진단 실행기를 사용할 것."
1. **T0/T1은 항상 통과해야 한다.** 실패한 채로 다음 작업을 시작하지 않는다.
2. **맵·Galaxy·데이터가 바뀌면 T2까지 돌린다.** 문법 오류는 T1이 못 잡는다.
3. **게임 동작을 바꿨으면 T3까지 돌린다.** 대조군 없는 T3 결과는 근거가 아니다.
4. **엔진 티어 전에 SC2와 에디터를 닫는다.** 고정 포트를 쓰므로 잔존
   프로세스가 결과를 오염시킨다.
5. **릴리스 맵을 검사하는 도구는 맵을 굽지 않는다.** 빌더를 고쳤으면
   재빌드가 먼저다. V1에서 옛 맵을 열고 통과 판정이 난 적이 있다.
6. **프로브가 이상하면 게임이 아니라 프로브를 먼저 의심한다.** 계측 두 열이
   서로 모순되면 대개 논리 슬롯 ↔ 런타임 ID 혼동이다.

## 새 데이터 파일 규약

생성된 데이터 파일(확장 좌표 등)은 **반드시** 다음을 담는다.

```json
{
  "version": 1,
  "source_map": {
    "path": "map/source/....SC2Map",
    "sha256": "...",
    "size": 3020527
  },
  "generated_at": "2026-07-22T...",
  "generator": "v2/verification/solve_expansions.py",
  "data": ...
}
```

빌더는 로드 시 `source_map.sha256`을 실제 베이스 맵과 대조하고,
다르면 **빌드를 실패시킨다.** 경고가 아니라 실패다 — 경고는 무시된다.
